# §11 Technical architecture

## 11.1 Reference architecture and stack

Build Margin as one TypeScript monorepo with a small number of named services. A service is a deployable with its own queue, SLO and on-call owner; everything else is a package. Do not split further at MVP.

**11-ARCH-001 — Services and responsibilities.** Implement exactly these services; add a new one only with a written SLO and a named owner.

| Service | Responsibility | Talks to | SLO owner metric |
|---|---|---|---|
| `web` (Next.js 16 / React 19, PWA) | All web surfaces (§10 screens 1–25), teacher console, parent digest web view, internal Admin/Compiler behind role gates | `api` | LCP/INP/CLS (11.14) |
| `mobile` (Expo SDK 57, Expo Router, EAS Update) | iOS/Android: same domain packages, camera capture, offline Cards, push | `api` | Crash-free sessions ≥99.5% |
| `api` (Node 22, Hono or Next route handlers; one process image) | Auth, tenancy, policy-object resolution, CRUD, entitlements, quotas, SSE fan-out | Postgres, Redis, `orchestrator`, `retrieval` | p95 non-AI request <250 ms |
| `orchestrator` | Task classification, route table (§08.2), prompt registry, cache-layout enforcement, Turn lint and effort-gate vetting (§04), failover, provider adapters | Providers, `retrieval`, `sandbox`, Redis | TTFT p50 <800 ms |
| `retrieval` | Hybrid search, graph expansion, rerank, citation resolution, grounding score | Postgres (pgvector), Voyage | p95 <120 ms |
| `ingest` (workers) | Two-pass parse, typing, segmentation, scheme structuring, mapping, ER mining, embedding, provenance ledger; the curriculum compiler DAG (§06) | Object storage, Postgres, batch APIs | Pages/hour; per-page confidence |

| `billing` | Stripe webhooks → entitlement service; regional PSP adapters; meter | Stripe, Postgres, Redis | Entitlement lag <5 s |

**11-ARCH-003 — Topology per region.** Deploy the full data plane (Postgres, Redis, object storage, `api`, `orchestrator`, `retrieval`, `marking`) in each residency region (`eu`, `uk`, `us`; `global` maps to `us` at launch). The control plane (Pack authoring, evals, billing ledger) is single-region with no pupil PII. *Acceptance:* a tenant with `residency=eu` produces zero rows in non-EU Postgres and zero provider calls to non-EU endpoints in the audit log for a 24-hour synthetic soak.

**11-ARCH-004 — Packs are data.** No board-, syllabus- or paper-specific logic in code paths; behaviour differences come from Pack rows (`boards.level_procedure`, `command_words`, `ao_weights`). *Acceptance:* `grep -rE "9609|0450|9708|9709|0580"` in `apps/` and `services/` returns only test fixtures and sample-chip strings. Why: SYNTHESIS §3.1 — a new board is a new Pack, never new code.

**11-ARCH-005 — One stack for teachers, parents and Admin.** The teacher console, parent digest and Compiler reuse `api`, `retrieval` and `marking`; they differ by role and policy object only. *Acceptance:* no second deployable or duplicated marking code path exists.

## 11.2 Data model

The data model has three planes: **Pack** (curriculum data, global, `org_id NULL`), **Learner** (everything derived from Attempts, tenant-scoped), **Tenancy/Trust** (orgs, consent, ledger, audit). Every learner-plane row carries `org_id`, `user_id`, `policy_version`, `created_at`; every Pack row carries `pack_id`, `pack_version`, `provenance`.

**11-DATA-002 — Attempt is write-once, append-corrections.** `attempts` rows are never updated except `teacher_override`, `mark_id`, `retest_due_at`; corrections create new rows linked by `supersedes_id`. *Acceptance:* a DB trigger rejects any other `UPDATE`.

**11-DATA-003 — Row-level security.** Enable RLS on every learner-plane table with policies `org_id = current_setting('app.org_id')` and role-scoped views: students read their own rows; teachers read `attempts` (fields: item, rung_reached, mark, gate_state, timestamps — never `response` text unless the assignment is `receipt_required` or the student shared) for their class only; parents read only the materialised `parent_digest` view. Pack tables are `org_id NULL`, read-only to tenants. *Acceptance:* the RLS test suite (≥200 cases across roles) passes in CI; a teacher token cannot `SELECT response FROM attempts` for a student outside their class (query returns zero rows, not an error).

**11-DATA-004 — Vector partitioning.** `chunks` is partitioned by `partition_key = coalesce(org_id::text, 'global')`; per-tenant USER uploads live in the tenant partition; a retrieval query names its partitions explicitly. *Acceptance:* the injection/isolation suite (§12.10) shows 0 cross-tenant chunk returns over 10,000 randomised queries.

**11-DATA-005 — Versioning.** `pack_version` and `policy_version` are pinned on `courses` and `sessions`; a Pack revision creates a new version and a migration note shown in the Course ("Pack updated to 2026–28 v3 — 2 syllabus points renumbered"); it never mutates history. *Acceptance:* re-running a Mark from a year-old Attempt with its pinned versions reproduces the same contract fields except `calibration_status`.

**11-DATA-006 — Learner state is a projection.** `learner_state`, mastery pips, readiness rings, Progress and the parent digest are computed only from `attempts`, `cards` reviews and `marks`; no surface reads chat text to infer mastery. *Acceptance:* deleting all `turns` for a user leaves every Progress number unchanged.

**11-DATA-007 — Retention fields are first-class.** Every table with pupil data has `retention_until` derived from the tenant policy object; a nightly job hard-deletes expired rows and writes a count to `audit_log`. *Acceptance:* the deletion-SLA test (11.13) passes.

## 11.3 API surface

The API is REST + SSE, versioned under `/v1`, JSON everywhere, typed with a shared OpenAPI document generated from Zod schemas; the mobile and web clients consume the same generated client.

**11-API-001 — Endpoint sketch.** Implement at minimum:

| Endpoint | Purpose | Notes |
|---|---|---|
| `POST /v1/sessions/{id}/turns` → SSE | One Turn in Learn/Practise/Mark; server picks route, applies gate/lint | Body `{message_parts[], intent?, effort?, client_msg_id}`; headers `x-route, x-model, x-cache-read-tokens, x-policy-version, x-stream-id` |
| `GET /v1/streams/{stream_id}?from={offset}` → SSE | Resume a stream after disconnect | Buffered in Redis for 15 min |
| `POST /v1/attempts` | Create Attempt (response, confidence, gate state) | Idempotent on `client_attempt_id` |

| `POST /v1/marks/{id}/challenge` | Challenge-a-mark: second family re-mark, escalation | Rate-limited 1 per Mark |
| `POST /v1/uploads` (multipart) → `{upload_id, scan_status}` | Files and photos; DLP scan; transient by default | Max 20/message; 25 MB each |

| `POST /v1/receipts` / `GET /v1/receipts/{id}.pdf` / `GET /r/{public_token}` | Learning Receipt issue, export, public view | §12.2 |
| `POST /v1/classes/{code}/join`, `POST /v1/assignments`, `POST /v1/marks/{id}/override` | Teacher-as-calibrator scope | Override ≤2 clicks: `{new_marks, reason_code}` |

**11-API-002 — Idempotency.** Every mutating endpoint accepts `Idempotency-Key` (UUID, 24 h window, keyed by user); replays return the original response with `Idempotent-Replayed: true`. Turn creation additionally dedupes on `client_msg_id` per session so a retried Send never creates two Turns or double-bills a Mark. *Acceptance:* a chaos test that retries every mutating call 3× under injected 502s produces exactly one row per logical action and one quota decrement.

**11-API-003 — Streaming parts.** SSE events are typed message parts: `text, thinking_summary, status, citation, math, diagram, tool_call, tool_result, mark_header, ao_card, command_word_check, advice, calibration, sources, provenance, card_suggestion, gate_prompt, intent_row, error, done`. Each carries `seq`, `part_id`, and for text `delta`. Clients render by part type; unknown types are ignored, never fatal. *Acceptance:* schema-validated in CI against the shared Zod definitions; a client built against v1 renders a v1.1 stream with new part types without error.

**11-API-004 — Errors are cards, not modals.** Errors return RFC 9457 problem details with a `user_message` suitable to render inline and an `retryable` flag. Never expose provider error text to the client. *Acceptance:* error snapshot test covers 429, 503, quota, policy-blocked, scheme-missing.

**11-API-005 — Rate limits by route class.** Enforce in `api` before any provider call: anonymous landing Mark 3/day/IP-hash and 1 concurrent; authenticated Turn 60/min burst 10; Mark per plan quota (11.10); upload 30/hour; export 2/day. Return `Retry-After`. *Acceptance:* k6 suite confirms limits and that a limited Turn returns a soft slow-down message, never a hard mid-session stop (SYNTHESIS §12 free-tier rules).

**11-API-006 — Policy object on every request.** `api` resolves `{residency, allowed_providers, retention_days, age_band, consent_mode, training_opt_in=false, school_safe}` from tenant + user and attaches it to the internal request context; `orchestrator`, `retrieval` and storage refuse a request without one. Where a user belongs to two tenants (family + school) the stricter value per field wins. *Acceptance:* unit tests for the merge; a request without policy fails closed with a logged 500, not a permissive default.

## 11.4 Retrieval (RAG) pipeline

Retrieval exists to put the right syllabus line, scheme point, examiner sentence or textbook paragraph in front of the model and the student, with a page-and-span address. Ingestion mechanics and the compiler stages are §06; this subsection fixes the retrieval-side contract.

**11-RAG-001 — Chunk by structure, never by fixed window alone.** Segment by document type before chunking: textbook `chapter → section → subsection → paragraph | figure | table | worked_example`; question paper `paper → section → question → part → marks`; mark scheme `question part → marking point | level band → guidance`; examiner report `question → commentary sentence group`; syllabus `unit → topic → learning objective`. Then apply HybridChunker at 256–512 tokens aligned to the embedding tokenizer, keeping tables, marking points and level grids whole and carrying `heading_path`. *Acceptance:* 0 chunks split a marking point, table row or level descriptor (structural lint on ingest).

**11-RAG-002 — Required metadata per chunk.** `doc_id, doc_type, board, syllabus_code, syllabus_version_years[], subject, level, paper, variant, series, question_id, marks, command_word, ao[], topic_path[], page_start, page_end, bbox[], figure_ids[], language, trust_rank, provenance, licence_id, source_hash, ingest_version, parse_confidence, partition_key`. Ingest rejects a chunk missing any non-nullable field. Why: a 2021 scheme line can be wrong for the 2026–28 syllabus; filters must run before similarity.

**11-RAG-003 — Query pipeline.** (1) Query understanding on the cheap route (§08.2): `{intent, syllabus_code, topic_guess, question_ref?, language}` as structured output; (2) SQL prefilter on `syllabus_code`, `syllabus_version`, `partition_key ∈ {global, tenant}`, `kill_switch=false`, `expiry > now()`; (3) hybrid: pgvector HNSW cosine on `halfvec(1024)` top-50 ∪ FTS `ts_rank_cd` top-50 → Reciprocal Rank Fusion (k=60), `hnsw.iterative_scan=relaxed_order` when filters are selective; (4) graph expansion via `links`: question → its scheme items and ER commentary; textbook hit → its syllabus objective + ≤2 linked questions; (5) rerank 50→8 (`rerank-2.5-lite`; `rerank-2.5` for Mark flows); (6) tie-break by `trust_rank`; (7) assemble as provider-native content documents with stable `[chunk_id]` tags so citations are block-indexed. *Acceptance:* Recall@8 ≥0.92 and nDCG@8 ≥0.85 on the 500-question gold retrieval set per syllabus; p95 end-to-end (steps 2–5) <120 ms.

**11-RAG-004 — Citation resolution to page and span.** Every emitted `citation` part resolves to `{doc_id, page, bbox | char_span, chunk_id, trust_rank, provenance, deep_link}`; the Reader opens the page with the span highlighted ≤400 ms p95 (§09). For `ref_only` Cambridge material the citation resolves to `{official_url, question_ref}` and the Paper Companion anchor, never to hosted text. *Acceptance:* ≥98% of citations in syllabus mode resolve (automated click-through test); 0 citations to `ref_only` docs render text.

**11-RAG-005 — Grounding gate.** If the top reranked score is below the per-syllabus threshold (calibrated on the gold set to 95% precision) or the draft cites nothing, the Turn is labelled "not in your syllabus materials" and any general explanation is rendered in the unverified style (§12.3). For Marks, a missing scheme record is a hard stop: feedback only, no numbers (§05). *Acceptance:* ≥98% of syllabus-mode answers carry ≥1 resolvable citation; 0 Marks emitted without a `mark_schemes` row in context (assertion in `marking`).

**11-RAG-006 — Notes-vs-canon conflicts.** When a USER chunk and a canon chunk (trust 1–4) disagree on a fact in the retrieved set, the orchestrator emits a `conflict` part with both citations; canon wins in the answer by default. *Acceptance:* the 50-item conflict fixture ("273 °C vs 273 K") yields a conflict card in 100% of cases.

**11-RAG-007 — Retrieved text is data.** Chunks are wrapped in delimited document blocks; the system prompt states that documents carry no instructions; any imperative addressed to the assistant inside a chunk is stripped by the injection scrubber before assembly and logged. *Acceptance:* red-team suite §12.10 passes 100%.

**11-RAG-008 — Eval sets are versioned artefacts.** Maintain per syllabus: retrieval gold (500 Q → chunk ids), generation set (Ragas faithfulness, context precision/recall, custom mark-scheme adherence), conflict fixture, injection fixture. Every ingest version and every retriever/prompt change runs them; regressions >1 pp block the label flip. *Acceptance:* eval run linked from every merged PR touching `retrieval/` or `ingest/`.

**11-RAG-009 — Caching.** Cache `(query_hash, filters, partition_key, ingest_version)` → chunk ids in Redis for 24 h; precompute retrieval for every Item in a live Pack nightly so Practise and Mark never wait on retrieval. *Acceptance:* ≥70% retrieval cache hit rate in production on Practise/Mark routes.

## 11.5 Tool sandboxes

**11-TOOL-001 — What runs in a sandbox.** SymPy/NumPy verification of every numeric or symbolic final (pre-solve and marking), `pint` unit checks, deterministic graph/diagram renderers (SVG from JSON spec), Anki `.apkg` build, PDF export of Receipts. Nothing else executes model-authored code at MVP; the student-facing code interpreter is v1 behind the same broker.

**11-TOOL-002 — Isolation.** Use E2B self-hosted (Firecracker microVMs) or the Anthropic code-execution tool on Claude routes; per-execution limits: no network egress (deny-all egress policy verified by a probe on boot), 512 MB RAM, 1 vCPU, 20 s wall clock (60 s for `.apkg` builds), 50 MB ephemeral disk, read-only base image with an SBOM, fresh VM per tenant-execution, no secrets mounted, no access to Postgres or object storage — inputs and outputs pass through the broker as JSON. *Acceptance:* a canary job that attempts DNS, TCP to 1.1.1.1, filesystem escape and env-var reads fails on all four every hour; failures page.

**11-TOOL-003 — Verification contract.** The orchestrator marks a numeric final `verified=true` only when the sandbox result matches to the tolerance in the Item (`abs_tol`, `rel_tol`, `sig_figs`); a mismatch renders both values with "check this" and never a confident single answer. *Acceptance:* 0 unverified numeric finals on STEM routes (assertion in the Turn lint).

**11-TOOL-004 — Client-side Pyodide.** Load Pyodide lazily (never in the chat route's initial bundle) for instant answer checking in Practise and offline Card maths; results are advisory and re-verified server-side before they touch an Attempt. *Acceptance:* Pyodide absent from the initial JS payload (bundle analysis in CI).

**11-TOOL-005 — Per-route tool allow-lists.** Each route in the route table declares its tools; a tutoring Turn may call `retrieve`, `verify_math`, `render_diagram`, `suggest_card`; it cannot call `delete_card`, `update_plan`, `send_notification`, `issue_receipt`. Tool calls outside the allow-list are dropped and logged as security events. *Acceptance:* unit test per route; injection suite confirms no privilege escalation via document content.

## 11.6 Realtime streaming

**11-RT-001 — Transport.** SSE over HTTP/2 from `api` (which proxies `orchestrator`); WebSocket only for the v1 voice pilot broker. Each assistant Turn has a `stream_id`; `orchestrator` writes parts to a Redis stream every ≤250 ms or every part boundary; `api` fans out. Buffers live 15 minutes after `done`.

**11-RT-002 — Resumability.** A client reconnecting with `from=offset` receives every part it missed, in order, exactly once; a Turn whose stream died server-side is finished by a worker, not restarted. *Acceptance:* the network-flap test (kill the connection at 10 random offsets per Turn, 200 Turns) loses zero parts and duplicates none.

**11-RT-003 — Streaming contract to the UI.** Optimistic user message <50 ms; `status` part at 800 ms if no text yet ("Reading the 9609 P2 mark scheme…"); "Taking longer than usual" + Stop at 6 s; Stop aborts the provider call within 300 ms and bills only consumed tokens; paint ≤90 characters per 16 ms frame; previous DOM immutable; unclosed math/code held as a skeleton until the part closes; CLS above the cursor = 0. *Acceptance:* Playwright trace on golden conversations measures each budget; CLS assertion in CI (11.16).

**11-RT-004 — Mark streaming order.** `mark_header` first, then `ao_card` parts in AO order, each within 8 s of the previous, `command_word_check`, `advice`, `calibration`, `sources`, `provenance`, `done`; the credited spans in a card are emitted with the card so highlights light up as it lands. *Acceptance:* synthetic 20-mark Mark shows first `ao_card` <8 s p95 and `done` <45 s p95 in the staging soak.

**11-RT-005 — Backpressure and failover.** Quotas and policy checks run before the provider call; provider 429/503/529 or TTFT >4 s triggers the failover path from the route table with `x-failover=1` in telemetry; the client sees the same stream id. *Acceptance:* chaos test with a blackholed primary provider completes ≥99% of Turns via fallback with no client-visible error.

## 11.7 Offline, PWA and sync

**11-OFF-001 — What works offline.** Cards review (due queue, two-button grading, interval hints), the Today list as last fetched, downloaded Course notes and syllabus tree with pips, the Reader for OWN/LICENSED-offline-permitted documents already opened, Receipt viewing, the Plan. Nothing that needs a model call pretends to work: Learn, Practise marking and Mark show the offline banner and queue nothing except Card reviews and draft text. *Acceptance:* airplane-mode E2E test on web (service worker + IndexedDB) and Expo (SQLite) completes 20 Card reviews and shows a correct due count after reconnect.

**11-OFF-002 — Sync model.** Client-generated UUIDs; an outbox of `card_review`, `draft_response`, `plan_accept` events with monotonic `client_seq`; server applies idempotently (11-API-002) and returns the authoritative FSRS state; conflicts resolve by "server FSRS state wins, client reviews are replayed in order". *Acceptance:* two devices reviewing the same deck offline then syncing produce a deterministic state equal to the ordered replay.

**11-OFF-003 — Offline storage limits and privacy.** Cache ≤200 MB per Course on mobile; encrypted at rest with the OS keystore; cleared on logout and on tenant policy `retention_days` expiry; no transcripts cached for under-18 school tenants beyond the current Session. *Acceptance:* logout leaves no readable Course data in app storage (forensic check in the release checklist).

**11-OFF-004 — PWA.** Installable on Chromebook/desktop; app shell cached; background sync for the outbox; offline banner is a system state (§10 screen 24), never a modal.

## 11.8 Multi-tenancy and the consent graph

**11-TEN-001 — Tenant types and membership.** `individual` (one consumer), `family` (parent-owned, ≤3 students on the Family plan), `school` (admin, teachers, classes, students), `tutor_centre` (school-like, 1:20–50 seats). A user may belong to several tenants; the stricter policy object per field applies (11-API-006).

**11-TEN-002 — Visibility matrix (FINAL).**

| Data | Student | Teacher (own class) | Parent (linked) | School admin | Margin staff |
|---|---|---|---|---|---|
| Turn transcripts | Own, full | Never (aggregate hint depth only) | Never | Never | Only with a logged support ticket the student opened, or a safety escalation |
| Attempts (item, rung, gate, mark, timestamps) | Own | Yes | Aggregates only | Aggregates | Evals in pseudonymised form |
| Answer text on Attempts | Own | Only for assignments marked `receipt_required` or student-shared | Never | Never | Calibration with consent |
| Marks and overrides | Own (when visible) | Yes, plus override | Trend only | Aggregates | Yes (pseudonymised) |
| Predicted grade | Own (Progress › Paper) | Gated papers only | Only if student enables | No | No |
| Memories | Own, editable | Never | Never | Never | Never |
| Receipt | Own; shares by link | When shared | When shared | No | No |

*Acceptance:* the RLS suite encodes this matrix cell by cell.

**11-TEN-003 — Consent graph for under-18s.** Model consent as edges, not flags: `guardian_links` (parent → student, with `consent_evidence`), `school_consents` (school → student cohort, with the DPA and the FERPA/COPPA school-official basis), each with `scope` (what processing it authorises: `study_data`, `digest`, `predicted_grade_share`, `voice`, `research_pseudonymised`) and `expires_at`. A processing action checks the union of valid edges for the required scope; missing scope fails closed. Age band `16_17` and `18plus` consumers self-consent under GDPR where the member-state age allows; `13_15` requires a school edge at launch [founder default: 16+ consumer at launch; 13+ consumer opens after the external consent audit, target month 9]; `u13` is never onboarded. *Acceptance:* consent coverage report shows 100% of `13_15` and `16_17` (where required by member state) accounts with a valid edge; an account whose last edge expires is frozen (read-only, export available) within 24 h.

**11-TEN-004 — Parent controls change nothing the student owns.** Parents set Study Hours, Quiet Hours, digest cadence and payment; they cannot read transcripts, edit memories, or unlock predicted grades. Controls may be adjusted by asking the assistant in the parent surface with an explicit Allow/Deny confirmation. Auto-removal of guardian scope on the student's 18th birthday (age band change), with notice to both.

## 11.9 Authentication, age assurance and school SSO

**11-AUTH-001 — Methods.** Passkeys first; magic link; Google, Microsoft, Apple sign-in; class code + school SSO. No passwords stored for new accounts; sessions are httpOnly, SameSite=Lax, 30-day sliding with device list and remote revoke in Settings.

**11-AUTH-002 — Age assurance path.** At "Save this Course": (1) self-declared age band (never full DOB retained after assurance); (2) signal checks: school-tenant membership, SSO directory attribute, payment-holder age for family plans, and an age-estimation classifier on usage signals in the style of the labs' age prediction (PROVISIONAL: vendor or in-house, decided by the DPIA); (3) for `13_15` and `16_17` where consent is required, the guardian or school edge (11-TEN-003). Uncertain bands default to the more protective band. Store `{method, confidence, checked_at}` only. *Acceptance:* a declared 19-year-old exhibiting strong under-16 signals is moved to teen defaults and asked to verify; DPIA documents the false-positive/negative trade-off.

**11-AUTH-003 — School SSO in v1.** SAML 2.0 and OIDC (Google Workspace for Education, Microsoft Entra), roster via Wonde and Clever/ClassLink connectors; MVP ships class codes only. Just-in-time provisioning maps directory roles to `teacher`/`student`; an SSO-provisioned under-16 inherits the school consent edge. *Acceptance:* a pilot school onboards in <1 day with no manual account creation.

**11-AUTH-004 — Anonymous first Mark.** The landing Mark runs under a device-bound anonymous principal (signed cookie, 24 h) with the strictest policy object (`residency` by geo-IP, `age_band=unknown` → teen defaults, no memory writes, transient upload). Converting to an account migrates the Mark and Attempt.

## 11.10 Billing, quotas and the meter

**11-BILL-001 — SKUs (PROVISIONAL on [E9]; numbers are [founder default]).** Student Monthly $8; Student "Until exams" $59 (entitlement `expires_at = last_paper_date + 7 days`, max 10 months, computed from the Course's exam dates); Parent/Family $19/month (≤3 students); School seat $10/student/year (invoice, not card); Tutor per seat; regional tiers −40% (KZ, IN, PK, NG, EG, TR) by billing country with Stripe Tax and local PSPs. Teacher role is free forever and needs no card.

**11-BILL-002 — Entitlement service.** Entitlements are derived server-side from `subscriptions` + `grants` (school seats, trials, grace) and cached in Redis; PSP webhooks only update `subscriptions`. Feature checks call `entitled(user, capability)`; the client never decides. *Acceptance:* revoking a subscription propagates to the meter in <5 s; a replayed webhook is a no-op.

**11-BILL-003 — Quotas and meter (FINAL free-tier rules from SYNTHESIS §12).** Counters per user per `session / day / week / month`: `levels_marks` (free 3/day; 6/day in exam-week grace from T−14 to the last paper; paid 40 Opus-class per month then soft slow-down to Sonnet-draft marking with a factual line), `points_marks` (uncapped, slow-down), `cheap_turns` (uncapped, slow-down), `uploads` (≥20/day free), `voice_minutes` (v1). Limits are published as plain numbers on `/v1/usage` and the Settings meter; grace and slow-down states are explicit fields. Slow-down means longer queue and cheaper route, never a hard stop mid-Session. *Acceptance:* zero silent limit changes — any change to a published limit requires a versioned `limits.json` change with a changelog entry visible in-app.

**11-BILL-004 — Until-exams SKU mechanics.** Purchase requires ≥1 Course with an exam date; expiry recomputes if the student edits dates (max 10 months from purchase); renewal offers the next series only after results day.

## 11.11 Observability, tracing and evals infrastructure

**11-OBS-001 — Traces.** Every request carries a W3C `traceparent`; every model call is a Langfuse span with the per-call fields defined in §08.12 (`policy_version, route, model, effort, cache_read_tokens, cache_write_tokens, ttft_ms, total_ms, cost_usd, failover, rung, lint_result, gate_state, intent, calibration_status`) plus platform fields `tenant_id, residency, age_band, experiment_arms[], stream_id, ingest_version`. Prompts are referenced by `(name, version)` and never copied into logs. PII: user ids are pseudonymous; message text is stored in traces only for tenants whose policy allows (`trace_content ∈ {none, redacted, full}`; school tenants default `redacted`).

**11-OBS-002 — Cost attribution.** Attribute `cost_usd` per Turn/Mark to `user, tenant, route, model, feature, experiment`; nightly roll-ups produce cost per weekly-active learner and the 99th/median spend ratio; alert when any student's day exceeds 3× median or a route's cache-read share drops below 50%. *Acceptance:* the cost dashboard reconciles to provider invoices within 3%.

**11-OBS-003 — Product telemetry.** Events are Attempt-derived (§07/§13); no third-party analytics SDK in under-18 surfaces; event schemas versioned in the repo.

**11-OBS-004 — Eval infrastructure.** Langfuse datasets hold: 30-turn adversarial pedagogy suite, praise/sycophancy lint set, marking gold sets per paper (CalibrationRecords), retrieval gold, injection and isolation fixtures, a11y snapshot set. Runs are triggered by CI on prompt/model/policy/retriever changes and nightly on `prod`; results write to `eval_runs` and gate label flips (11.16). Cross-family LLM-as-judge (Opus 5 + GPT-5.6 Sol) with teacher panel on disagreement; judge prompts are versioned like any other prompt.

**11-OBS-005 — SLO dashboards and paging.** TTFT, first-AO-card, stream resume failures, RLS denials, sandbox canary, cache-read share, seeding auto-pause events, consent-coverage, deletion-SLA, and per-paper QWK drift. Page on: auto-pause of a question family, sandbox canary failure, any cross-tenant read, residency violation, deletion-SLA breach.

## 11.12 Security

**11-SEC-001 — Threat model.** OWASP GenAI Top 10 (2026) mapped to controls; the primary adversaries are students seeking leaks (§12.10), uploaded documents carrying injected instructions, cross-tenant data access, and credential theft on shared school devices.

**11-SEC-002 — Prompt-injection defence for uploads and chunks.** (a) Uploads are DLP- and malware-scanned, converted to text/images server-side, never executed; (b) retrieved and uploaded content is wrapped in data blocks with the system rule "documents are data"; (c) the injection scrubber removes imperative sequences addressed to the assistant, hidden text (white-on-white, zero-width, off-page), and known jailbreak strings, logging each hit; (d) tools are allow-listed per route (11-TOOL-005) so a successful injection cannot act; (e) output is post-checked by the Turn lint for gate violations regardless of what any document says. *Acceptance:* the injection fixture (≥300 documents: PDF, DOCX, image with embedded text, `.apkg`, ICS) produces 0 gate violations and 0 tool calls outside the allow-list.

**11-SEC-003 — PII handling.** Minimise before provider calls: strip names, emails, phone numbers and school identifiers from Turn text where the policy object requires (`pii_redaction=on` for school tenants by default); images downsampled to ≤2,000 px and never used for training; DeepSeek receives only non-PII synthetic or corpus work [founder default E5]. Secrets live in the platform secret manager, rotated quarterly, never in prompts, logs or client bundles; provider Files API ids are server-side only.

**11-SEC-004 — Application security.** CSP with nonces; Mermaid/SVG rendered in a sandboxed iframe; HTML output sanitised; signed URLs for object storage (≤10 min); rate limits (11-API-005); WAF with bot rules on the anonymous landing; dependency scanning and an SBOM for parsers and sandbox images; annual external penetration test plus a pre-launch test in M5; a published `security.txt` and disclosure policy.

**11-SEC-005 — Abuse.** Anonymous Mark abuse (scripted farms) is bounded by device-bound principals, IP-hash limits and a proof-of-work challenge above threshold; account sharing is detected by concurrent-device heuristics and answered with a soft prompt, never a lockout in exam week.

**11-SEC-006 — Secure defaults on shared devices.** School tenants: session expiry 12 h idle, "not my account" switch on the sidebar, no persistent transcripts on device (11-OFF-003).
