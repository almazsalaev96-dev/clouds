# §03 Table-stakes parity with frontier chat products

## 03.1 Scope and the parity rule

Margin must be usable as a student's only chat product. A student who leaves ChatGPT for Margin must lose nothing from the core chat loop and gain the learning engine (§04–§05). This section fixes what "nothing" means, in what order it ships, and how a reviewer verifies each item. It does not describe how the learning engine behaves inside these features; it cross-references the owning section. "Only chat product" is a claim about the *loop*, not about coverage: at MVP five syllabus codes have a Pack, and 03-SCOP-006 fixes what happens for every other subject a real student takes.

## 08.3 Prompt-caching architecture

Cache economics dominate: Anthropic cache reads are 10% of input price (2.5% on Fable 5.1), 1 h writes 2×; Gemini cached input is 10% plus storage per hour; GPT-5.6 cached input is 90% off. An uncached Sonnet 5 Learn Turn costs ≈$0.019; cached ≈$0.0114 [AR§6].

**Prompt layout (08-CACH-001).** Every request is assembled in this fixed order; blocks 1–3 are byte-stable and carry `cache_control` (1 h TTL); nothing dynamic appears before block 4.

```yaml
prompt_layout:
  1_persona:        # mode system prompt (Learn/Practise/Mark) + voice preset + lint rules; ≥1,024 tokens combined with block 2
  2_pack_static:    # Course Pack slice: syllabus outline, verbatim command words + AO ceilings, generic marking principles, misconception index; versioned by pack_version
  3_task_static:    # Mark routes only: structured scheme for this question part + 3–5 scored anchors + ER insights (keyed by `question_ref`)
  --- last cache breakpoint ---
  4_learner_state:  # ≤600 tokens: mastery of the open node, misconception prior, seen-solution flags, entry rung, phase, exam date
  5_retrieval:      # ≤8 chunks × ≤300 tokens, wrapped as <document> data, trust_rank order
  6_history:        # compacted Session history (auto-cached by the provider at top level)
  7_user_turn:      # message + attachments (images last; images invalidate the messages cache when added/removed)
```

| ID | Requirement | Acceptance |
|---|---|---|
| 08-CACH-002 | Blocks 1–3 contain no timestamps, no user identifiers, no random ordering, no per-request ids; the Pack slice is serialised with sorted keys and a content hash stored as `cache_key`. | Golden conversation replayed twice yields identical bytes for blocks 1–3 (hash test in CI). |
| 08-CACH-003 | Per-model minimum prefix respected: Opus 5 ≥512 tokens, Sonnet 5 ≥1,024, Haiku 4.5 ≥4,096 (pad the trivial-route prefix above 4,096 or disable caching for it — never pay a write that cannot be read). | Unit test per model asserts prefix ≥ minimum or `cache_control` absent. |
| 08-CACH-004 | CI asserts `cache_read_input_tokens > 0` on the second Turn of every golden conversation for every route that caches; a prompt deploy that drops the golden cache-hit rate fails the pipeline. | CI job `cache-assert` green; failing fixture exists. |
| 08-CACH-005 | Production targets, stated per traffic shape because one number for Mark routes is not achievable by construction: **≥60% of input tokens billed as cache reads across chat routes (blended)**; on Mark routes **≥80% on assignment and Paper-runner traffic** (many scripts per `question_ref` inside one TTL) and **≥25% on ad-hoc traffic** (a student marking an arbitrary past-paper part, where a 1 h write costs 2× input and a single read returns 0.1×, so the break-even is 1.1 reads per write). The blended denominator **excludes** classifier (08-RT-017) and orchestrator-vet tokens, which sit below Haiku's 4,096-token cache minimum and can never be cache reads; counting them makes the target unachievable arithmetic rather than an engineering goal. | 08-CACH-006 | Mark routes pre-warm the block-3 cache for a question part when a Paper runner starts or a class assignment opens, so the first Mark of a batch pays the write once. | First Mark after pre-warm shows `cache_read_input_tokens > 0`. |

| 08-CACH-010 | **A 1 h cache write is a bet; the router computes the odds before placing it.** Block 3 (the structured scheme + anchors, keyed by `question_ref`) is written with a 1 h TTL **only** when ≥3 Marks for that `question_ref` are already queued — a class assignment, an open Paper runner, or a seeded batch. ## 08.7 Degradation ladder

The ladder is the only mechanism allowed to change a route after the classifier has chosen it (08-PRIN-001). It is ordered, per task class, config-driven (`routing.yaml → ladders[]`), and every step is visible to the student. Quality never drops silently: a cheaper or different model is a labelled event, a Mark from a route not calibrated for that paper carries the **Provisional** badge (05-MARK-010, 05-GATE-003), and a Session never ends because of a step.

**08-DEGR-001 Triggers and detection windows.** Five trigger classes; each is evaluated per `(provider, model, region)` and, for budgets, per tenant and per student.

| Trigger | Detection | Scope | Auto action |
|---|---|---|---|
| `outage` | HTTP 529/503/500 on ≥20% of calls in a 60 s window with ≥20 calls, or provider status page `degraded/major` for the model, or 3 consecutive connection failures | provider × model × region | Open the circuit; move traffic to the next rung |
| `latency` | TTFT p50 >4 s or p95 >8 s over 60 s (Learn); first-AO-card p50 >12 s (Mark); vision transcript p50 >30 s | provider × model × region | Open the circuit at half weight (50% of traffic to next rung), full at 2× threshold |
| `rate_limit` | 429 with `retry-after` >2 s, or >5% 429s in 60 s, or provider ITPM/OTPM headroom <15% | provider × model | Honour one `retry-after` ≤2 s; otherwise next rung; page if headroom <15% for 10 min (08-PRIN-006) |
| `budget` | Student day >3× the rolling 7-day median spend for the plan (03-LIM-006, 11-COST-002); tenant day >100% of `quotas.tenant_budget_usd_day`; platform day >120% of forecast | student / tenant / platform | Slow one rung; flag; never block silently; school admin and finance alert |
| `eval_fail` | Canary or nightly gate breach on a new model or prompt version (§08.9); seeded-QA auto-pause (05-GATE-005) | policy version × paper | Label flip to the previous version; Mark routes for the paused family drop to the second family with the Provisional badge |

### Resolution and precedence

**08-POL-007 Resolution path.** At session establishment (`POST /v1/sessions`) and on every request that carries no session, `policy.resolve(user_id, course_id)` = `merge(defaults, tenant_policies…, user_prefs)` where tenant policies are ordered `school | tutor_centre` → `family` → `individual`. The result is cached in Redis under `(user_id, course_id, tenant_set_hash, policy_config_version)` with a 60 s TTL, pinned to the Session as `policy_version` for its lifetime (13-GATE-004), and its `hash` is written on every Turn, Mark and log line. A request that reaches the orchestrator without a resolved policy fails closed with a logged 500 (11-API-006) — never a permissive default.

**08-POL-008 Merge rules per field class.** Precedence is "school > parent > student" in the sense that the more accountable party sets the ceiling and the stricter value always wins; a student can only make their own settings stricter.

| Field class | Fields | Merge rule |
|---|---|---|
| Enum lattice | `residency`, `consent_mode`, `logging_level`, `age_band` | Most protective on a fixed lattice: `residency` eu > uk > us > global (never widened by a lower tenant); `logging_level` none > redacted > full; `age_band` the youngest asserted band |
| Permission booleans | `deepseek_allowed`, `features.*`, `training_opt_in`, `research_pseudonymised` | Logical AND (any tenant that forbids, forbids). Exception: `features.incognito` — a school may not disable a student's incognito Session, only exclude it from assignment work |
| Restriction booleans | `zdr_required`, `school_safe`, `pii_rules.redaction` | Logical OR (any tenant that requires, requires) |
| Sets | `allowed_providers`, `consent_scopes` | Intersection |
| Retention numbers | `retention_days.*` | Minimum, floored by legal minima (`receipts`, `audit_log` are fixed by 11-PRIV-004 and never reduced) |
| Quotas and budgets | `quotas.*` | Owning tenant of the Course (08-POL-006); the platform ceiling in `config/limits.yaml` always applies |

**08-POL-009 Enforcement points.** Each is an independent gate; none trusts the others.

| # | Point | Enforces | Failure mode |
|---|---|---|---|
| 1 | API gateway | policy attached, `age_band` route allow-list, quota counters | 500 fail-closed, alarm |
| 2 | Router (§08.2) | `allowed_providers`, `excluded_models`, `deepseek_allowed`, ladder rung skipping (08-DEGR-002) | rung skipped; if no rung remains, the route refuses with the factual §08.7 string |
| 3 | Adapter (§08.11) | `endpoints` host/region, no-training flag, ZDR header, `max_tokens` | adapter throws `PolicyViolation` before the socket opens |
| 4 | Redaction filter | `pii_rules` on every outbound payload and every trace write | request blocked, security event |
| 5 | Retrieval | per-tenant vector partition, `trust_rank`, `school_safe` corpus filter | empty result, logged |
| 6 | Storage / RLS | `org_id` isolation, `retention_days` on write (TTL columns) | RLS denial paged (11-OBS-005) |
| 7 | Jobs (export, deletion, batch, evals) | residency of the worker, `research_pseudonymised`, batch provider allow-list | job refuses to start |

**08-POL-010 Tests (all in the stage-2 and nightly suites, 11-CICD-001).** (a) Merge unit tests: ≥40 cases covering every field class and every tenant combination, including the dual-membership case and the "student cannot loosen" case. (b) Residency: nightly `SELECT count(*) FROM audit_log WHERE residency IN ('eu','uk') AND provider_region NOT LIKE 'europe-%'` = 0 (11-PRIV-002); a synthetic EU tenant runs one Turn, one Mark, one upload, one voice attempt and one appeal per hour for 24 h. (c) DeepSeek: 08-POL-002 matrix plus a payload lint asserting no free text, Course id or transcript in any DeepSeek request. (d) ZDR: 08-POL-003 fixture. (e) Fail-closed: a request with the policy header stripped returns 500 and writes `policy_missing` — a permissive default is a CI failure. (f) Boot validation: the whole tenant table is validated against the schema on deploy; one invalid tenant blocks the release.

**08-POL-011 A provider without a contractual no-training assertion may not receive the data assets.** `mark_scheme_items`, `examiner_insights`, generated Items, Pack-derived `OWN` prose, any `LICENSED` text and any `USER` text are refused for such a provider at the adapter (enforcement point 3 above), before the socket opens. Today that provider is DeepSeek, whose permitted payloads are exactly two: `public_stimulus` (the published question text of a past-paper Item) and `numeric_presolve` (the numeric task and its candidate answer). Why: the bulk work DeepSeek is cheap at is precisely the structured mark-scheme layer and the examiner-insight paraphrases that SYNTHESIS §12 names the company's primary data asset, and a 50% batch discount is not a price worth paying for it; the same rule is enforced on the storage side by 11-SEC-003. The exposure is a row in `compliance/risk-register.yaml`, re-reviewed each time a provider is added. *Acceptance:* a payload-class lint on every adapter whose `capabilities.no_training_assertion = false` fails on any `content_class` outside that adapter's permitted set; a planted `mark_scheme_items` payload on the DeepSeek adapter raises `PolicyViolation` in the adapter unit test; the risk register carries the row and names its owner.

## 08.9 Eval gates per model or prompt change

A prompt change, a model swap, an effort remap, a route-table edit and a Pack pin change are all the same kind of change: a new `policy_version`. They ship through the pipeline of 11.16 and are gated by the suites of §13. This subsection fixes what runs, what promotes, what rolls back, and what the student can see about which version marked their script.

### What a version is

**08-EVG-001 The pinned bundle.** `policy_version` is a semver-dated label (`2026.09.2`) over a manifest that pins everything that can change an answer. Nothing else is allowed to vary between two calls with the same `policy_version`.

```yaml
policy_version: 2026.09.2
prompts:            # Langfuse (name, version), immutable once labelled
  learn.system: v31        practise.system: v18      mark.levels.system: v27
  mark.points.system: v14  orchestrator.vet: v9      classifier.intent: v7
routes: routing.yaml@rev 412        # models, effort, fallbacks, budgets, ladders
schemas: Mark@3, Item@2, Card@1, Plan@1        # the only legal spelling (00-APP-007)
packs:  {9609: "9609:2026-2028@2026.11.2", 0450: "0450:2026-2027@2026.09.1",
         9709: "9709:2026-2028@2026.10.2"}     # version_tag form only (00-APP-007)
retriever: {embed: voyage-4@int8-1024, rerank: rerank-2.5-lite, ingest_v: 19}
lints: {turn: v6, praise: v4, copy: v11}
graders: {judge.pedagogy: v5, judge.praise: v3}
labels: {prod: 2026.09.2, canary: 2026.09.3-rc1, previous: 2026.09.1}
```

| ID | Requirement | Acceptance |
|---|---|---|
| 08-EVG-002 | A Session, a Paper runner and a Mark are pinned to the `policy_version` current when they started; a promotion never changes a Session in flight (13-GATE-004). Marks store the version in `provenance`. | Fixture: promote mid-Session; the Session's remaining Turns report the old version; the next Session reports the new one. |
| 08-EVG-003 | Rollback is a **label flip** (`prod` → previous manifest), ≤60 s to 100%, with no code deploy and no cache rebuild beyond the prefix re-warm (11-CICD-006). | Timed drill each release: flip and back, measured. |
| 08-EVG-004 | An AI coding agent may open a version PR but may not change a gate threshold, a gold set, a grader prompt or a §15.A system prompt without a named human reviewer from the owning role (13-EVAL-006, 13-GATE-005). | CODEOWNERS enforced; attempted agent merge blocked in a test PR. |

### Pre-merge (stage 5 of 11-CICD-001)

Any PR touching `prompts/`, `orchestrator/`, `marking/`, `retrieval/`, `config/routes*` or `config/policy*` runs the subset below against the candidate manifest; all thresholds are hard fails.

| Suite (§13) | Scope on a prompt/model change | Threshold | Budget |
|---|---|---|---|
| Pedagogy adversarial subset (§13.2) | ≥50 dialogues × 30 turns, all personas, cross-family simulated student | leak <5%; praise <5%; hand-back present 100%; ladder descent 0 outside `rung_relief` | ≤30 min |
| Marking gates (§13.3) | ≥40 gate scripts per **touched paper**; full per-paper set if the marking model or `mark.levels.system` changed | within the paper's published tolerance; signed error ±0.3/10; hallucinated scheme reference = 0 | ≤30 min |
| Retrieval and grounding (§13.4) | gold query set for the touched Packs | Recall@8 ≥0.92; unsupported-sentence rate ≤1% | ≤6 min |
| Injection and tool safety (08-TOOL-007) | full document-injection fixture | 0 behaviour changes | ≤4 min |
| Structured outputs (§08.4) | ≥20 valid / ≥20 invalid per touched schema; repair rate | 100% validation; repair <3% | ≤3 min |
| Cache assertion (08-CACH-004) | golden conversations per route | `cache_read_input_tokens > 0` on Turn 2 of every caching route | ≤2 min |
| Cost and latency (§08.10) | golden conversations, token baselines per route | cost within ±15% of the route budget; TTFT p50 within +20% of baseline | ≤5 min |
| Classifier (08-RT-020) | 2,000-message labelled fixture | accuracy ≥0.95; gradable→trivial misroutes <0.5% | ≤3 min |

**08-EVG-005** A model swap additionally runs: the full per-paper marking gates for every gated paper the model marks, the trivial/classifier gold set, the tokeniser-baseline job (Claude 4.7+ tokenisers are ~30% heavier, so `max_tokens` and context budgets are re-derived per model, 08-PRIN-005), and a fresh cache-minimum check (08-CACH-003). *Acceptance:* a swap PR without a tokeniser-baseline artefact fails stage 2.

### Canary and promotion

**08-EVG-006 Canary.** 5% of traffic by sticky `user_id` hash for ≥2 h, **≥6 h during exam weeks**, excluding school tenants that opted out and any tenant with a timed paper in progress (11-CICD-002). Marking versions canary at 5% of Marks but with 100% cross-family second marking during the window regardless of the sampling rate in force, so every canary Mark has an independent comparison.

**08-EVG-007 Promotion criteria** — all must hold over the canary window with n ≥ the stated minimum; otherwise the label does not flip.

| Metric | Threshold | Min n |
|---|---|---|
| Seeded-QA marks within tolerance (08-ENS-005) | 100% of seeded families | 60 seeded Marks |
| Canary vs `prod` QWK per touched paper | not worse by >0.02 | 40 Marks/paper |
| Second-family disagreement >1 level | ≤ baseline + 1 pp | 40 Marks |
| Production leak sample (§13.2 grader on live Turns) | <5% | 200 Turns |
| Praise lint on live Turns | <5% | 200 Turns |
| TTFT p95 | <1.5 s | 500 Turns |
| 5xx | <0.5% | — |
| Challenge rate (§08.6) | not up >1 pp vs the 7-day baseline | 100 Marks |
| Cost per Turn / per Mark | within +15% of the route budget | 500 Turns |
| Cache-read share | ≥50% of the pre-canary share per route | — |

**08-EVG-008 Automatic rollback triggers** (evaluated every 5 minutes on the canary cohort; any one flips the label back and pages the owner): any promotion metric breached; seeded-QA auto-pause on any question family (05-GATE-005); schema validation failure rate >1%; repair rate >6%; a safety-classifier regression (distress recall below the fixture floor); provider `stop_reason: refusal` rate >0.5%; or a `route_expected != route_actual` rate >5% (08-PRIN-001). Rollback is automatic and unattended; the incident is opened afterwards (RB-05, 08-DEGR-007).

**08-EVG-009 Post-promotion.** After 100%, the previous manifest stays warm for 7 days; the nightly full suites (13-GATE-002) run on the new version; the calibration report (§05) is re-published if any per-paper number moved, and a per-paper number may not move without the content lead's signature.

### What the student sees

**08-EVG-010 Model provenance on the Mark.** Every Mark carries a provenance chip resolving to `{model_family, model, second_marker, policy_version, pack_version, calibration_state, marked_at}` (§12.9 transparency; §05.2 contract). Tapping it opens "How this was marked", which names the marker in plain words ("Marked by Claude Opus 5, second-checked by GPT-5.6 Sol · scheme version 9609 P2 2026.3 · marking version 2026.09.2"). Re-marks after a version change never silently overwrite: the original Mark is kept and the new one is labelled "Re-marked on the new marking version — your earlier mark is below".

**08-EVG-011 Change log.** `release_notes` (11-CICD-007) exposes, in Settings › What changed and on the calibration page, every version that altered marking, limits or Packs, with the suite results attached. A change to a paper's calibration state or to a published limit that does not appear in the log is a release-blocking defect (02-INV: zero silent limit cuts).

**08-EVG-012 Dated hazards gate the config, not just the calendar.** CI fails if any route references a model whose `valid_to` has passed, or whose hazard `effective` date (11-COST-008: Gemini Flash price doubling 1 Jan 2027; Haiku 4.5 retirement from 15 Oct 2026; Sonnet 5 / Opus 5 / Fable 5.1 commitment floors) is <30 days away without an `ack_by` field naming the reviewer and a linked successor-eval run. *Acceptance:* clock-advanced test fails the build 29 days before a hazard without an ack, passes with one.

## 08.11 Vendor abstraction layer

Every model call in the product goes through one interface. The Vercel AI SDK 7 carries transport and UI streaming; provider-specific capabilities that the differentiators depend on — Anthropic `cache_control`, effort and citations, Gemini thinking level and context caches, OpenAI reasoning effort, Bedrock/Vertex regional hosts — are exposed through **our** adapter contract using the native SDKs underneath. Why: an abstraction that flattens to the lowest common denominator throws away exactly the features §08.3 and §08.4 are built on [AR§19, AR§21].

### The interface

```ts
// packages/llm/src/contract.ts — the only surface product code may import
export interface ModelAdapter {
  readonly id: ProviderId;                     // 'anthropic' | 'google' | 'openai' | 'deepseek' | ...
  readonly capabilities: Capabilities;         // static, asserted by conformance tests

  complete(req: LlmRequest): Promise<LlmResult>;                 // non-streamed
  stream(req: LlmRequest): AsyncIterable<StreamPart>;            // typed parts (§09.8)
  structured<T>(req: LlmRequest, schema: SchemaRef): Promise<Validated<T>>;  // §08.4
  tools(req: LlmRequest, tools: ToolDef[]): AsyncIterable<StreamPart>;       // allow-listed, §08.5
  vision(req: LlmRequest, images: ImageRef[]): Promise<LlmResult>;
  cache: { plan(blocks: PromptBlock[]): CachePlan; minPrefixTokens(model: string): number };
  batch: { submit(jobs: LlmRequest[]): Promise<BatchHandle>;
           poll(h: BatchHandle): Promise<BatchStatus>; results(h: BatchHandle): AsyncIterable<LlmResult> };
  embed?(texts: string[], opts: EmbedOpts): Promise<Float32Array[]>;
  rerank?(query: string, docs: string[], k: number): Promise<Ranked[]>;
  countTokens(req: LlmRequest): Promise<number>;                 // per-model tokeniser
  health(): Promise<{ ok: boolean; region: string; latencyMs: number }>;
}

export interface LlmRequest {
  route: RouteId;               // 08-RT-0NN — the adapter never infers the route
  policy: PolicyObject;         // §08.8; adapter refuses if host/region/model not permitted
  blocks: PromptBlock[];        // ordered per 08-CACH-001, each {role, content, cacheable}
  effort: 'none' | 'low' | 'medium' | 'high';   // mapped per provider by the adapter
  maxTokens: number; stopReasonsExpected?: string[];
  schema?: SchemaRef; tools?: ToolDef[]; images?: ImageRef[];

  // Payload classification — set by the caller, asserted by the adapter (08-POL-002, 08-POL-011).
  // These four fields are what the DeepSeek guard and the redaction filter actually read;
  // an LlmRequest without them fails type-checking, so the guard cannot be skipped by omission.
  jobClass: 'interactive' | 'pre_solve_second_solver' | 'bulk_corpus' | 'eval';
  piiClass: 'none' | 'pseudonymous' | 'direct';
  contentClasses: ContentClass[];   // 'public_stimulus' | 'numeric_presolve' | 'own_pack'
                                    // | 'licensed' | 'user_upload' | 'learner_text'
  contentResidency: 'eu' | 'uk' | 'us' | 'global';

  idempotencyKey: string; traceparent: string;
}

export interface LlmResult {
  text?: string; object?: unknown; toolCalls?: ToolCall[];
  usage: { inTokens: number; outTokens: number; cacheReadTokens: number; cacheWriteTokens: number;
           reasoningTokens?: number };
  costUsd: number;              // computed from config/pricing.yaml + policy uplift (08-COST-001)
  model: string; host: string; region: string; stopReason: string;
  ttftMs: number; totalMs: number; raw: unknown;   // raw kept per 08-SCH-007
}
```

| ID | Requirement | Acceptance |
|---|---|---|
| 08-VND-001 | Product code (orchestrator, marking, retrieval, jobs, UI) imports only `packages/llm`. A direct import of `@anthropic-ai/sdk`, `@google/genai`, `openai` or an HTTP client to a provider host outside `packages/llm/adapters/*` fails the lint. | ESLint `no-restricted-imports` rule + a CI grep over the monorepo; a planted violation fails the build. |
| 08-VND-002 | **No vendor-specific prompt text in product code or prompts.** Prompts contain no provider names, no "as Claude", no model-specific formatting hacks, no XML-vs-Markdown branching by vendor; provider-shaped wrapping (Anthropic XML block tags, Gemini `systemInstruction` placement, OpenAI developer-message conventions) is applied by the adapter from the neutral `PromptBlock[]`. | Prompt lint: regex over `prompts/` for provider names and model ids = 0 hits; the same golden Turn rendered through three adapters produces the same visible content and passes the same Turn lint. |
| 08-VND-003 | Capability gaps are declared, never emulated silently. ### Conformance and onboarding

**08-VND-007 Adapter conformance suite** (`pnpm test:adapters`, run per PR against record/replay fixtures and nightly against live providers with a $5/day cap): 60 cases per adapter — a plain completion; a stream with mid-stream cancellation; a stream that is cut and resumed; typed part ordering; a 4-block cached prompt asserting `cacheReadTokens > 0` on the second call; a below-minimum prefix asserting no cache write is attempted; a strict-schema call with a valid and an invalid response plus one repair; three tool calls including one typed error; a vision call with a 2,000 px downsample; a batch of 20 with poll and partial failure; token counting within ±2% of the provider's own counter; cost within ±1% of the price table; a 429 with `retry-after`; a 529; a refusal `stop_reason`; a policy violation (forbidden host) refused before the socket opens; and a redaction assertion (no `pii_fields` in the outbound payload). *Acceptance:* every adapter passes all 60 or is not registered in `routing.yaml`.

**08-VND-008 Feature flags.** Each adapter is behind `provider.<id>.enabled` and each capability behind `provider.<id>.cap.<name>` (11-CICD-003), so a provider incident is a flag flip, not a deploy, and a newly onboarded provider ships dark. Flags carry an owner and a 30-day expiry for `release`-class flags.

**08-VND-009 Onboarding a new provider in <1 week** — the checklist is the definition of done: day 1 adapter skeleton + `capabilities.json` + pricing rows with `valid_from`; day 2 conformance suite green on record/replay; day 3 live-key conformance in `staging`, region and residency mapping added to `endpoints` (§08.8) and to `/legal/subprocessors` with the 30-day tenant objection window opened (11-PRIV-007); day 4 route table entry as a **ladder rung only**, behind a dark flag; day 5 §08.9 gates on the routes it can serve; day 6–7 canary at 5%. Promotion to a *primary* route always requires the full per-paper marking gates or the full pedagogy suite for the class it would serve. *Acceptance:* a rehearsal in M4 onboards one unused provider end-to-end inside five working days, evidenced by the PR trail; no product-code file changes in that PR other than config.

### Trace linkage

**08-LOG-002** One trace per user action. Span hierarchy: `request` → `policy.resolve` → `classifier` (parallel) → `retrieval` (`embed`, `search`, `rerank`) → `llm.call` (one per model call, including each failover rung and each self-consistency run) → `tool.*` → `validate` → `lint` → `persist` (Attempt/Turn/Mark write). Background work joins by link, not by parent: a batch job carries `links[]` to the Attempt trace that caused it (Card generation, pre-solve, second mark), so a Mark shown to a student resolves to every call that produced it. The `mark_id` and `turn_id` are queryable keys in Langfuse, so "show me every call behind this Mark" is one lookup — the same lookup the support tool and the appeal reviewer use. *Acceptance:* pick 20 random Marks; each resolves to a complete call set including the second marker and any repair call, with no orphan spans.

**08-LOG-003** Client to server: the web and Expo clients propagate `traceparent` on the stream request and report `first_paint_ms`, `stream_resumes`, `abandon_before_first_token` back onto the same trace, so a latency complaint is answerable end to end (§11.14 budgets).

### Redaction and retention

**08-LOG-004** The redaction filter runs **before** the trace leaves the process, not in the pipeline: `logging_level: none` drops all C fields at source; `redacted` applies the `pii_rules` scrubber (names, contacts, school names, faces blurred on images, free-text scrub) and stores a content hash for eval replay; `full` is permitted only for consenting `18plus` consumers and synthetic tenants (08-POL-005). Teen bands are pinned to `none`. Retrieved chunk text is stored as ids only unless `full`. *Acceptance:* a provider-payload and trace-payload lint in CI fails on any `pii_fields` name; a teen-tenant soak produces zero C fields across 24 h.

**08-LOG-005** Retention follows 11-PRIV-004: traces `none` metadata 90 days, `redacted` 30 days, `full` 14 days; `raw_output` for schema routes 90 days (08-SCH-007) subject to the tenant's `retention_days`; account deletion purges traces keyed by `user_hash` within 7 days, which is why `user_hash` — not a raw id — is the join key everywhere. Metrics roll-ups are aggregate-only and survive deletion (they contain no `user_hash` beyond k ≥ 20 buckets). *Acceptance:* the deletion-SLA test asserts zero trace rows for the deleted `user_hash` at hour 168, and that the cost dashboard totals are unchanged by the deletion.

Dashboards: *Routing* (`route_expected == route_actual` rate, rung distribution, failover reasons by provider/region); *Cost* (§08.10 report inputs live, per route/model/tenant, cache-read share, batch share); *Latency* (TTFT p50/p95 by route and region, first-AO-card, tool time, queue time); *Quality* (lint pass rate, leak and praise sample rates, repair rate, schema failures, `verified` share on STEM finals, per-paper QWK and challenge rate); *Safety* (affect tags, refusals, classifier fail-closed events); *Policy* (EU/UK calls by `provider_region`, DeepSeek calls by job class, ZDR excluded-model attempts).
