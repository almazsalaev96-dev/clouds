*This file contains §00 (How to use this document), §01 (Mission, principles, positioning) and §02 (Users, jobs, moments, scenarios) of the Margin master build prompt. It depends on `designs/SYNTHESIS.md` (the adjudicated decisions, which it must not contradict) and cross-references §03–§15 by number for everything it does not own. # §00 How to use this document

## 00.1 Who executes this, and in what order to read it

This document is the build specification for **Margin** (working name; see §01.7). Its reader is the executing AI coding agent, or the engineering team an agent leads. Treat it as a contract, not an inspiration: every numbered requirement is a test you will be held to, every "Never" row is a lint you will write, and every "Why:" is the evidence that stops you re-litigating a decision.

**00-USE-001 Reading order.** Read in this order before writing code: §00 → §01 → §02 (this file) → §03 (parity) → §04 (learning core) → §05 (exam engine) → §06 (library) → §07 (learner memory) → §08 (orchestration) → §09 (design system) → §10 (screens) → §11 (architecture) → §12 (safety) → §13 (quality gates) → §14 (roadmap) → §15 (appendices). Do not start a section's build until you have read the sections it cross-references. Acceptance: the first pull request of the build contains a `DECISIONS.md` that lists every requirement ID this PR touches; a PR touching an ID from a section not yet read is rejected in review.

**00-USE-002 Roles.** Four roles execute this document; an agent may hold more than one, but each PR names which role authored it.

| Role | Owns | Must never |
|---|---|---|
| Builder | Code, migrations, prompts, tokens, screens | Merge without the §13 gate report attached |
| Content engineer | Packs, structured mark schemes, gold sets, misconception library (§05, §06) | Enter a `scraped` provenance class or paste board wording without a licence (§06) |
| Evaluator | Eval suites, calibration runs, praise lint, adversarial students (§13) | Lower a floor to make a paper pass; the fix is content or method, never the bar |
| Founder liaison | Founder-owned decisions (§00.3), licensing, budgets | Silently choose a non-default; every non-default is a written decision |

**00-USE-003 Vocabulary is fixed.** Use only the canonical nouns from SYNTHESIS §3 in code, UI strings, telemetry and docs: Course, Pack, Item, Attempt, Turn, Mark, Card, Session, Plan, Source, Receipt, Class; the Learner Graph (the projection of Attempts into mastery, misconceptions and calibration, §07); the Examiner Twin (the calibrated per-paper marker, §05); the Effort Gate and Help Ladder (§04); the Learning Receipt (§12). Modes are **Learn · Practise · Mark**. Intent chips are **Teach me · Check my steps · Just the answer**. Mastery states are **Unseen · Shaky · Secure · Exam-ready**. Acceptance: a repository grep for `streak`, `quiz mode`, `tutor mode`, `explain mode`, `exam mode` as user-facing strings returns zero hits; the glossary in §15 is the only place synonyms appear, and only to map them to canon.

**00-USE-004 The scoping knife.** Before building any feature, answer in the PR description: "Which Attempts does this create or improve?" A feature with no answer is not in the MVP (SYNTHESIS §3.1). Why: every metric, mastery update, teacher view and Receipt is a projection of Attempts; features that do not touch them are cost without learning.


## 00.2 Non-negotiables

These hold for every release, every tenant, every model swap, every "quick fix". They are not trade-offs; they are the product. Each is enforced by a test named in the owning section. If a requirement elsewhere in this document appears to conflict with one of these, this list wins and the conflict is a bug to report (§00.6).

| ID | Non-negotiable | Enforced by |
|---|---|---|
| 00-NON-001 | **The Effort Gate.** No solution content on a gradable Item before an Attempt, a plan, or "don't know where to start" plus one sentence of what the student does know. There is no fourth path: the 90-second time-box (04-GATE-002) is a way of *reaching* the third path, not a way around it — it ends with one required line naming what the student tried or what is blocking them, and exiting through it runs the whole seen-solution script (label, 24–72 h retest, near-transfer Item). The gate is a state on the Attempt, never a refusal in prose, never rate-limited. | §04; 30-turn adversarial suite, leak <5% (§13); fixture `timebox_farm`: 10 consecutive time-box exits carry `seen_solution=true` and a scheduled retest in 100% of cases |
| 00-NON-002 | **No Mark without a mark scheme in context; no number below gate.** If no structured scheme record exists, the product gives feedback and spans only. Below the §05 ship gate a paper shows spans and feedback, never a mark or a predicted grade. | §05.6; CI asserts 0 marks emitted without `mark_scheme_items` |
| 00-NON-003 | **No sycophancy.** No person-praise, unearned praise, agreement with an incorrect claim, softened mark, exclamation mark, emoji, "Great question" or therapy-speak in any Turn or Mark. | Praise lint before paint, regenerate once, template fallback; weekly audit <5% (§04, §13) |
| 00-NON-004 | **No streaks, no shame, no engagement optimisation.** No daily streaks, loss animations, confetti, overdue counters, mascots, or loss-framed notifications. DAU and minutes are guard-rails, never targets. | Lint on string table and motion tokens (§09); KPI tree (§14) |
| 00-NON-005 | **No submittable coursework.** NEA/IA/EE/personal-statement requests switch to draft-feedback mode; every assignment produces a Learning Receipt. | §12; eval set of coursework prompts, 0 submittable outputs |
| 00-NON-006 | **Three-provenance content model.** Every document is `OWN`, `LICENSED` or `USER`; there is no `scraped` class in code; `USER` never enters global retrieval; per-document kill switch; 24 h takedown SLA. | §06; type system rejects a fourth class |
| 00-NON-007 | **Never host or mirror board PDFs; no Cambridge mark-scheme viewer.** Papers deep-link to official pages; grid wording is paraphrased unless licensed; extracts ≤2 sentences or ≤40 words, attributed, audit-logged. | §06 extracts policy; storage lint |
| 00-NON-008 | **Teen-safety parity.** Item-for-item match with ChatGPT for Teens: age assurance, consent under 16, Study/Quiet Hours, break reminders, no romantic or companion behaviour, no ads, parental controls without transcript access, persistent Article 50 disclosure. | §12; consent audit 100% for under-16 school-tenant users |
| 00-NON-009 | **No efficacy claim that is not pre-registered.** No "2× learning", no multiplier, no grade-uplift claim outside the §14 study plan. The marketing number equals the product number. | Copy review checklist (§14); legal sign-off |
| 00-NON-010 | **Never "replaces teachers"; never "official" or "endorsed"; never the name beside "Cambridge".** Non-affiliation notice in footer and store listing. | String lint; store-listing template (§14) |
| 00-NON-011 | **Every pixel passes the §09 checklist.** Tokens only (no raw hex, no raw px outside the scale), one accent hue, no `ease-in`, no #000, no motion on Send, WCAG 2.2 AA gates, CLS above the cursor = 0. | §09.16 pixel-QA release checklist as CI; Storybook visual diff |
| 00-NON-012 | **Every prompt, model, routing or policy change passes the §13 gates** before it reaches a user: adversarial pedagogy suite, praise lint, per-paper marking gold sets, Recall@8 ≥0.92, cache-read assertion, CWV and TTFT SLOs. | CI required checks; policy version pinned per Session |
| 00-NON-013 | **A Course, not a chat.** Home has no "New chat"; a conversation without a Course is an Ask and never counts as study; there is no study toggle to lose; the mode chip is always visible. | §10 screen 3; e2e test |
| 00-NON-014 | **Turn discipline.** Every Learn-mode Turn ≤120 words unless depth was requested, one move, at most one question, explicit hand-back. Marking cards are exempt. | Orchestrator rejects >1 question; <2% of Turns >150 words (§04) |
| 00-NON-015 | **Verified before spoken.** Every numeric or symbolic final passes SymPy/Pyodide; quotes come only from loaded set texts, else "I can't confirm that quote"; every Item is pre-solved and the key held before tutoring. | §08 verification tools; eval: 0 invented quotes |
| 00-NON-016 | **"Just the answer" is honoured, never refused, after one attempt** — labelled Seen solution, retested at 24–72 h, never counting toward Secure. Homework due in ten minutes is legitimate. What "the answer" is differs by Item and is a **visible state, never a sentence of prose**: on points and short-answer Items it is the full worked solution; on a levels Item ≥8 marks the chip reads "Full plan + one paragraph" with the tooltip "Model essays unlock after your own marked attempt", and once that student's own Attempt on that Item has been Marked the full model answer is available under the same seen-solution script. | §04.5; eval: 0 refusals and 0 scope sentences post-attempt; suite case `demand_essay_after_mark` delivers the model answer |

None is aesthetic.


## 00.3 Resolving ambiguity: precedence, provisional decisions, founder-owned defaults

**00-AMB-001 Precedence.** When two sources disagree, resolve in this order and record the resolution in `DECISIONS.md`: (1) `designs/SYNTHESIS.md`; (2) this document, where the section that *owns* the topic wins over a section that merely mentions it (ownership is the "Owner" column of SYNTHESIS §4 and the §NN headings here — marking belongs to §05, tokens to §09, routing to §08, personas to §02); (3) `designs/JUDGING.md` for the reasoning behind a ruling; (4) the research appendices (`research/*.md`) as evidence, never as decisions; (5) the three visions (`designs/vision-*.md`) only for colour. Acceptance: no PR cites a research file as the authority for a product behaviour.

**00-AMB-002 Do not re-open rulings.** Every decision in SYNTHESIS was adjudicated in JUDGING §3. If you believe a ruling is wrong, build the default, write a one-paragraph objection with evidence into `OBJECTIONS.md`, and continue. The founder reviews objections weekly (§00.6). Do not fork behaviour behind a flag "just in case" unless the ruling itself names an A/B.

**00-AMB-003 Three statuses.** Every requirement is FINAL unless labelled. **PROVISIONAL** means: build the stated default and implement the flip condition as a measurable event (an A/B result, a licence signed, a human–human line measured). **[founder default]** means: build the recommended default from the table below, tag every dependent string, migration or config key with the decision number so a reversal is a search-and-replace, not a rewrite. ## 00.5 How to use the appendices (§15)

§15 holds the artefacts you paste, not the rules you interpret. Use it as follows.

**00-APP-001 System prompts per mode (§15.A).** Copy the Learn, Practise and Mark system prompts verbatim into the prompt registry with their version hash; never edit inline in application code. Any change is a new version that passes §13 before routing (00-NON-012). The cached prefix (persona + Pack) must stay byte-stable and precede all dynamic content (§08).

**00-APP-002 Marking rubric templates (§15.B).** Use the levels and points templates as the *shape* of `mark_scheme_items`; the *content* for each paper comes from the Pack. A template field left blank is a build error, not a default.

**00-APP-003 Question-tagging schema (§15.D).** Every Item you create, import or generate validates against the schema (syllabus node, AO split, command word, tariff, cognitive-demand tag, provenance, stats). Reject on validation failure; do not coerce.

**00-APP-004 Prompt templates (§15.E).** Feedback template (task → process → self-regulation), distress script, coursework refusal, "Just the answer" deal script, probe card wording, debrief template. The strings there are canonical; §01.6 gives the voice rules they obey.

**00-APP-005 Glossary (§15.F).** The only place a synonym may appear. If a term you need is missing, add it to the glossary in the same PR that introduces it.

**00-APP-006 Open questions for the founder (§15.H).** Mirrors 00-AMB-004 with the full reasoning. Add a question there only when 00-AMB-005 cannot settle it.

**00-APP-007 Identifier and version grammar (normative).** Every durable identifier has exactly one form. `common@1` in §15.C.1 is the machine-readable copy; this table is the human one. ## 00.6 Reporting progress, and what to ask the founder and when

**00-REP-001 Weekly build report.** Every Friday, one file `reports/YYYY-WW.md`, ≤600 words, in this order: (1) gate dashboard deltas (leak rate, praise rate, per-paper QWK, TTFT, cache share, cost per student); (2) requirement IDs closed this week, with evidence links; (3) IDs at risk for the current milestone (SYNTHESIS §13 table); (4) objections filed (00-AMB-002); (5) founder decisions needed, each with the default you are building meanwhile and the date the default becomes expensive to reverse. No prose about effort or mood. Acceptance: a reader who opens only the report can name the current milestone's exit criteria and which are red.

**00-REP-002 Per-PR contract.** Title starts with the requirement IDs touched. # §01 Mission, principles, positioning

## 01.1 Mission, vision, category

**01-MIS-001 Mission (FINAL wording; use verbatim in the README and the About screen).** *Margin exists so that every student, whatever their school, earns the marks their understanding deserves — and understands more because of how they earned them.* The measurable form is the north star in §14: **Unaided Mark Gain per study hour (UMG/h)** — the change in a learner's unaided, timed component-mark estimate on unseen Items from gated papers, per hour studied.

**01-MIS-002 Vision (three horizons, FINAL).** Year 1: the best Cambridge International exam tutor in the world, with published calibration per paper. Year 2: ten-plus curricula through the compiler, the product schools recommend by name, a community of creators. Year 3: a platform for any curriculum, one million paying learners, the category's reference dataset on what moves exam outcomes. Nothing in the vision says "replace teachers" or "faster than school"; nothing in the build may either (00-NON-010).

**01-MIS-003 One-sentence definition (FINAL; product copy may shorten, never extend).** Margin is an AI study workspace that marks like an examiner and teaches like a tutor: it grounds every explanation in the student's own syllabus, mark schemes and examiner reports; marks work per Assessment Objective with quoted evidence and a published agreement number; and schedules what to learn next so that more marks are earned per hour studied — for Cambridge International first, and for every curriculum after.

**01-MIS-004 Tagline (FINAL for product surfaces; marketing may test variants).** Primary: *"They know everything. We know your exam."* Mark surface: *"Marked like an examiner. Explained like a tutor."* Acceptance: no other tagline string exists in the string table.

**01-MIS-005 Category sentence.** Margin is an exam-outcome company built as a data platform — calibration data, structured mark schemes, the Learner Graph, school trust — with a chat interface on top that matches a frontier chat. Why: the labs own the model and the prompt; they do not own paired examiner marks per paper, syllabus-tagged item banks with live statistics, or a learner graph a minor's school can endorse. Build the data assets as first-class systems (§05, §06, §07), not as by-products of chat.

## 01.4 The honest answer to "why not ChatGPT Study Mode + Save My Exams"

**01-HON-001 The answer (FINAL; use it, unedited, when a student, teacher, journalist or investor asks).**

> ChatGPT, Gemini and Claude are better general assistants than we are, and we run on them. Their study modes are free, and for a student who already knows what to practise and can judge their own work, they are enough. What they do not have is your exam. None of them knows that "Analyse" in 9609 caps you at AO3, that a developed chain needs two links, or that repeating the business name is not application; none holds the mark scheme when it marks, so the same essay gets a different grade every time and a kinder grade than an examiner would give; none remembers what you know rather than what you typed, so week six starts from zero; and none will publish how often it agrees with a real examiner, because it does not measure it. Save My Exams and its peers have the notes and the papers but mark short answers only, publish no accuracy, and run on the boards' tolerance rather than a content model a school can endorse. Margin does one job those two halves cannot do together: it marks your work the way your paper is marked, shows you the sentence that lost the mark and the examiner's own words about it, remembers the gap, and schedules the retry before the exam. When we cannot yet do that for your paper to the standard we publish, we say "not yet calibrated" and give you feedback without a number. What you pay for is marking volume, not access: three marked essays a day are free forever and six a day in exam weeks, every points answer is marked without a cap, and nothing about how you learn — the gate, the ladder, Cards, probes, the Plan — is ever behind the price; the paid tier buys forty calibrated Marks a month. And for a subject we have no Pack for, we say so and label the help "not exam-grounded" rather than pretend. We are not smarter than the models. We are prepared for your exam, and we can prove it.

## 01.6 Brand voice rules and example strings

The voice is **an examiner who is on your side**: short, specific, declarative; examiner vocabulary explained in plain words; certain where the scheme is certain, explicit where it is not. These rules bind every Turn, Mark, notification, empty state, error, email and store listing. §09 owns typography; §15.E owns the full template set; this section owns the rules.

**01-VOICE-001 Rules (lint where marked L).**
1. Task before person: talk about the answer, never about the student's character or intelligence. (L: person-praise list.)
2. The most valuable sentence first: the highest-yield lost mark, the due count, the next block. No preamble.
3. Name the scheme, not your opinion: "Recommend — a supported decision is required. None found, so AO4 cannot reach Level 3," never "I feel the evaluation is weak." The assessment objective and the level are interpolated from the Pack, never written into a string (15-CMD-005): a three-AO syllabus has no AO4.
4. One move per Turn: a question, a hint, or a micro-example — not two. (L: >1 question mark rejected.)
5. Numbers are tabular, exact and sourced: "agreement 0.82 · 312 scripts"; a number without its n or its series is removed.
6. Never an exclamation mark, emoji, "Great question", "Let's dive in", "Don't worry", "Take a breath", or any therapy-speak. (L.)
7. Uncertainty is stated as a band or a refusal to guess: "4–5 of 9"; "I can't confirm that quote." Never a confident wrong specific.
8. Refusals, where policy requires one, are one sentence and name the allowed alternative. Never a lecture on integrity.
9. Days-to-exam is information, never pressure: "Paper 2 · Thursday 09:00 · 3 days," never "Only 3 days left!"
10. Vendor names are chips, never headlines; "Cambridge" is a fact about the syllabus, never a badge.
11. Plain words for examiner terms on first use in a Session: "application (facts true of *this* business)".
12. In distress: warm, brief, honest, back to the plan, signpost if crisis language appears; never diagnose, never companion.
