# §05 The exam engine

## 05.1 Scope, principles and the Examiner Twin

The exam engine is the part of Margin that marks like an examiner. It owns four things: the **Examiner Twin** (one calibrated marker per paper), the **Timed Paper** runner, the **original question generator**, and the **handwriting pipeline**. Everything it emits is a **Mark** attached to an **Attempt** (SYNTHESIS §3.1); nothing it emits is an official mark, and the copy must say so.

| ID | Requirement |
|---|---|
| 05-SCOP-001 | Build two engines, never one: a **points engine** (M/A/B/DM/DB/FT marking points, ECF, SymPy recompute) and a **levels engine** (per-AO level grids, best-fit, evidence rules). A `mixed` scheme runs both and sums. *Acceptance:* a 9709 P1 question and a 9609 P4 essay produce Marks from different code paths with different eval suites. |
| 05-SCOP-002 | Never emit a numeric mark without a `mark_scheme_items` record for that exact question part in the model context. If no scheme exists (an unseen upload, a user's own question), run **feedback-only mode**: spans, command-word check, next-mark advice, no number, no level. *Acceptance:* CI test with an empty scheme returns `total_band=null` and `visibility.show_number=false`. **Why:** every positive AI-tutoring RCT gave the tutor a verified key; ungrounded marks are the #1 student complaint ("ChatGPT predicts me 16 and I get 3"). |
| 05-SCOP-003 | The Examiner Twin is instantiated **per paper** (`syllabus_code × component`), with its own gold set, marker-instruction version, calibration numbers and release state. A Pack may have some papers `gated` and others `provisional`. |
| 05-SCOP-004 | Mark per AO and per level, never holistically. The total is a sum of AO marks; the UI shows the total as a **band** (`low/modal/high`), never a bare point. **Why:** LLMs over-score short essays and under-score long ones when marking holistically; per-criterion marking with quoted evidence removes most of the length effect (arXiv 2603.23714). |
| 05-SCOP-005 | Every credited point quotes a span of the student's own answer. A credited point without a span is a bug that fails the eval and the release gate (§13). |
| 05-SCOP-006 | Expert-marked boards (Cambridge, Edexcel, AQA, OCR, WJEC, IB written papers, AP FRQs) use these engines. Machine-scored exams (SAT, UNT, ЕГЭ Part 1, JEE) get the **machine-scored (IRT) engine** in v2 (§05.13). IB IA/EE and NEA get **criteria coaching** with "teacher marks first" and never a submittable draft — specified at 05-SCOP-011, with the coursework-mode surface in §09/§10 and the honesty posture in §12. English Literature and Psychology essays are excluded from the MVP marker (human–human reliability too low to validate; GM§B4c). |
| 05-SCOP-010 | **What we do not mark is published, not implied.** Every paper carries `pack.papers[].markable ∈ {full, feedback_only, not_marked}` with a `reason` string. `not_marked` covers components assessed away from a script — 9702 P3 and 9701 P3 (practical, performed at a bench), every practical-performance component, and any component whose evidence is not a written response. The Course setup sheet and the calibration page render the list verbatim; the reason string for a bench paper reads "This paper is assessed at the bench; we can rehearse the planning and analysis paper (P5) instead." *Acceptance:* a request to mark a `not_marked` component returns the reason string and offers the rehearsable sibling paper; no Mark row is written. |
| 05-SCOP-011 | **Criteria coaching is a fourth mode, not a fourth engine** (IB IA/EE, NEA, EPQ, SBA, and every component in 05-SCOP-010's `not_marked` or coursework set; v2). It reuses the levels engine's machinery and changes four things. (a) **No mark, ever:** `total_band = null`, `visibility.show_number = false`, and the `per_ao` objects carry `criterion_id` and `descriptor_relied_on` with `level: null` — the output is "which criterion this paragraph is serving and what the descriptor asks for that is not there yet", never a level and never a predicted grade. (b) **Teacher marks first:** where a Class exists, the criteria view is read-only for the student until the teacher of record has recorded their own criterion levels; the student sees "Your teacher marks this; I can show you what each criterion asks for." (c) **Draft-feedback mode is mandatory** (00-NON-005): every Turn writes a Learning Receipt entry and no Turn emits a sentence the student could paste (§12). (d) **Provenance:** criteria descriptors are board editorial text and enter a Pack only as `own_paraphrase` unless a licence says otherwise (06-PACK-004). *Acceptance:* the coursework eval set produces 0 numeric outputs, 0 predicted grades and 0 submittable paragraphs; a student in a Class with no teacher mark recorded sees the read-only state. |
| 05-SCOP-007 | All marking prompts, grids, anchors and marker instructions are **Pack data** selected by `boards.level_procedure`, `syllabus_code`, `syllabus_version`, `paper` and `question family`. A new board is a new Pack, never new code. *Acceptance:* adding 0450 requires zero changes under `engine/`. |
| 05-SCOP-008 | Latency and streaming, all **p95**: header ≤2 s, first AO card ≤8 s, full Mark ≤45 s for levels items; points Marks ≤15 s. Header, then AO cards in AO order, then command-word line, then advice, then calibration line. The answer's span highlights light up as each AO card lands. The only p50 figure anywhere in the product is the funnel metric "landing → Mark ≤90 s" (§14). |
| 05-SCOP-009 | Cost per Mark and the per-plan quota are **read, never restated here**: unit costs come from the route table and cost dashboard (§08.10) and change when the second-family sampling rate changes (100% of levels Items ≥12 marks for the first two series per paper, 05-PIPE-007, is the expensive window); quotas come from the versioned limits config (§11) and are rendered per §14.6. The engine reads both from the policy object, never hard-codes either, and never hard-stops mid-Mark: a Mark that begins finishes. *Acceptance:* no numeric cost or quota literal exists under `engine/`. |

## 05.2 The Mark object: output contract

The Mark is a JSON document persisted against the Attempt and rendered by the Mark view (§10.7). The contract below is FINAL (SYNTHESIS §8.1). The wire object is **closed** (`additionalProperties: false` in `Mark@3`, 15.C): a field addition is made by bumping the schema version to `Mark@4` and updating 15.C, this subsection and the fixtures in 05.12 in the same PR; removals and renames are never made. Every JSON example printed in §05 is a fixture in `schemas/examples/` and is validated against its `$id` in CI — an example that fails its schema is a build error, not a typo.

| ID | Requirement |
|---|---|
| 05-MARK-001 | Every `credited_spans[].quote` and `partial_spans[].quote` must be a verbatim substring of the confirmed transcript at `[char_start, char_end)`. Post-lint rejects the Mark otherwise and regenerates once; a second failure routes to the second family. *Acceptance:* fuzz test inserting fabricated quotes → 100% rejected. |
| 05-MARK-002 | `per_ao[].marks` sums to `total_band.modal`; each `marks` lies inside the band range of the `level` chosen in the scheme; `level` exists in the grid. Violations are schema errors, not warnings. |
| 05-MARK-003 | `reason_code` is an enum: `SINGLE_LINK · ASSERTION_NO_LINK · GENERIC_NOT_CONTEXT · DATA_NOT_USED · EVAL_IN_ANALYSE · TERM_REPEATED_IN_DEFINITION · WRONG_STAKEHOLDER · NO_WORKING · UNITS_MISSING · SIG_FIG · CONTRADICTION · ILLEGIBLE · OUT_OF_SCOPE · ATOM_NOT_MET · NOT_IN_INDICATIVE_VALID_ALT · DUPLICATE_POINT`. It is nullable on an omitted point (glyph `Ø`, nothing offered). Two members are constrained: `NOT_IN_INDICATIVE_VALID_ALT` is legal **only** where `awarded > 0` **and** `show_teacher_flag = true` — it means "valid under the grid's descriptor, absent from `indicative_content`, credited, teacher should see it"; a point that fails one atom of a conjunctive rule is `ATOM_NOT_MET` with `awarded = 0`, and a point the grid cannot justify at all is `OUT_OF_SCOPE` in `uncredited_attempts`. *Acceptance:* the schema validator rejects `NOT_IN_INDICATIVE_VALID_ALT` on `awarded: 0`; the 05.12(b) fixture exercises `ATOM_NOT_MET`. **Why:** indicative content is a guide, not a checklist (AQA/Cambridge generic principles); valid alternatives must be credited but a teacher must be able to see them, and an uncredited point tagged as a credited alternative silently inverts that rule. |
| 05-MARK-004 | `missing_points[]` names the highest-yield absent evidence per AO in the scheme's own terms (paraphrased), never a model answer. Maximum three per AO. |
| 05-MARK-005 | `command_word_check` sets the **AO ceiling** — which AOs are on offer at all — from the Pack's command-word table, and produces the coaching line. It may cap the level of the ceiling AO at the value the Pack's table names for that command word (`command_words[].uncapped_level`, default 2 for a missing judgement); it never sets a level *inside* an AO that is on offer, and it never lifts one. Where the AO's own grid awards a level below the cap, the grid wins and the Mark records `cap_binding: false`. The `coaching_line` interpolates and never hard-codes an AO: `"{Command} — {requirement}. {finding}, so {ceiling_ao} cannot reach Level {n}."` (§15.E owns the string; `{ceiling_ao}` comes from `CommandWord@1.ao_ceiling`, so a three-AO Pack such as 9708 renders AO3). One sentence, examiner voice, no exclamation marks (§09 microcopy). |
| 05-MARK-006 | `application_check` is mandatory on any Item with a `context` block (case study, insert, data response). A span passes only if it uses a fact from `context.case_facts` or a figure/constraint that is true only of this business. `passed[]` and `failed[]` are both arrays of span references, never counts, and `len(passed) + len(failed) == tested` is asserted in the post-lint. |
| 05-MARK-007 | `examiner_warnings[]` are drawn only from `examiner_insights` rows whose `heuristic` fires on this answer; text is our paraphrase with `series` shown. Never quote an ER verbatim without a licence (§06.2). |
| 05-MARK-008 | Exactly one `primary_action`. Kinds: `rewrite_paragraph · add_working · redo_calculation · answer_the_command_word · add_context · retry_unaided`. It targets the AO with the largest `(max − marks) × reachability`, where reachability is 1.0 for the next level up and 0.4 for two levels up. |
| 05-MARK-009 | `total_band`: `modal` = the **sum of the per-AO medians** (or of the awarded points), computed by code after the ensemble — never the median of the run totals, which does not in general equal the sum of the per-AO medians and would break 05-MARK-002. The run totals are kept in `provenance.self_consistency.totals` for audit only. `low/high` = modal ∓ `scheme.tolerance`, clamped to `[0, tariff]`. The UI copy under the band reads "Real examiners disagree by about ±{tolerance} on items like this." *Acceptance:* a property test over 1,000 synthetic ensembles asserts `sum(per_ao.marks) == total_band.modal` in 100% of cases. |
| 05-MARK-015 | `data_reference_check` is mandatory and non-null wherever `context.kind = "data_response"` (9609 P2, 9708 P2/P4 and every paper whose stimulus is a table or figure). A span passes if it quotes a value from `context.data_series[]`, performs a correct operation on two or more of those values (SymPy-verified), or names a labelled trend in them. Shape and lint are identical to `application_check` (`tested`, `passed[]`, `failed[]`, span refs). A failure attaches `DATA_NOT_USED`. **Why:** on a data-response paper the credit-bearing behaviour is using the supplied figures; the cover-the-name test alone fails a student who manipulates the data correctly and names no company fact. |
| 05-MARK-016 | `total_band.exact = true` only where **every** marking point in the Mark is deterministically verified — SymPy recompute or exact-match against the key — and no point rests on a model judgement. An exact Mark renders as one integer with the `exact` badge ("4/5 · exact"); every other Mark renders as `low ── modal ── high` with the tolerance sentence. `exact` and a non-zero tolerance are mutually exclusive; a Mark asserting both fails the post-lint. **Why:** a band on a SymPy-verified arithmetic mark states uncertainty the engine does not have, and students read that as hedging. |
| 05-MARK-010 | `calibration_status.state ∈ {gated, provisional, uncalibrated}`. `uncalibrated` forces `visibility.show_number=false` and `total_band=null`; the Mark still renders spans, checks and advice. `provisional` shows the number with the badge "Practice estimate — not yet calibrated". |
| 05-MARK-011 | `confidence` per AO is the agreement across self-consistency runs and the second family (1.0 = identical level and mark everywhere; <0.6 sets `show_teacher_flag=true` on that AO). Never show a percentage to students; render as "high / medium / check with teacher". |
| 05-MARK-012 | The Mark is immutable once persisted. Re-marks, challenges and teacher overrides create new Mark rows linked by `supersedes`. The Attempt points at the current Mark; every prior Mark stays auditable. |
| 05-MARK-013 | Points-engine Marks use the same envelope with `per_point[]` instead of `per_ao[]`: `{marking_point_id, awarded, glyph ∈ {✓,×,Ø,BOD,CON,RE,GA,ECF,NC,I}, quote, char range, recompute: {expected, seen, tool: "sympy"}, ecf_from}`. |
| 05-MARK-014 | Word budget: the rendered rationale for a 20-mark item is ≤220 words excluding quotes; for a ≤5-mark item ≤80 words. Marking cards are exempt from the 120-word Turn budget (§04) but not from the praise lint. |

## 05.6 Calibration and release gates

This subsection restates the FINAL rule in SYNTHESIS §8.5 as testable gates. The unit of gating is the **paper** (Examiner Twin instance); readiness `gold_seeded → gated → live` is computed, never set by hand.

**The unit is a gradable response, not a script (05-GATE-001a).** A P4 script contains two 20-mark essays and yields 2 responses; a P2 script yields 6–8. Every count in §05, §06 and §13 — gold-set size, per-family minima, fairness-bucket n — is in **responses**. The founder budget [E6] is stated in scripts because that is how markers are paid; the gold-set manager stores both and the dashboard shows both.

**Gold sets (05-GATE-001).** Tier 0: Example Candidate Responses and specimen answers (seeds, never sole truth; enter via teacher upload where SSH-only). Tier 1: partner-school scripts double-marked **blind** by two teachers with the official scheme, **both marks kept** — this yields the human–human line per question family. Tier 2: teacher overrides confirmed by a second teacher or contracted examiner. Stratify by tariff, command word, handwritten/typed, answer-length **tercile** and region/L1, with a minimum cell size of 15 responses; a cell below 15 is reported as "insufficient n", never as a passing cell. Synthetic answers are used only for robustness suites, never for headline metrics. Budget and staffing are FOUNDER-OWNED [E6] — [founder default]: ≈300 double-marked scripts × 6 papers with ex-examiner rates; without it, no published numbers and no predicted grades.

**Sizing per family (05-GATE-001b).** A family gates on **≥50 double-marked responses**; below that the family is `insufficient_n`, ships feedback-only, and is listed as such on the calibration page. A paper whose funded budget cannot reach 50 responses in every family gates only the families it covers — partial gating is normal and is displayed per family, never averaged into a paper-level claim. PROVISIONAL against [E6]: the default budget of ≈300 scripts per paper covers roughly 8 families at this minimum for a two-essay paper and fewer for a data-response paper; where it does not, the honest action is to gate fewer families, not to lower the minimum.

**Ship gate per paper (05-GATE-002, FINAL).** Marking becomes visible (numbers shown) when the paper meets **both**:

| Item class | Absolute floor (a) | Human-line rule (b) |
|---|---|---|
| Exact-match / MCQ (9708 P1/P3, 9709 MCQ components) | key agreement 100% on a 200-response audit set · option-to-key mapping verified against the official key | **Not applicable.** Two markers of a key agree by construction, so the human line is degenerate; the paper records `human_line: "n/a"` and gates on (a) alone, without a provisional badge |
| Machine-scored (IRT) score estimate (UNT, SAT, ЕГЭ Part 1, JEE; v2, §05.13) | ≥90% of the live bank inside the fit and DIF bounds of 05-IRT-006 · every scored item `calibration_n ≥ 300` · `SE(θ) ≤ 0.30` at the cut scores · score RMSE ≤ the exam's published SEM (05-IRT-008) | **Not applicable** for the same reason: the scored unit is a key, not a judgement. `human_line: "n/a"`; a paper with any scored item below `calibration_n = 500` gates **provisional** (05-IRT-012) |
| Points (9709, 0580, 9609 calculations) | exact ≥97% · within ±1 ≥99.5% · per-marking-point F1 ≥0.90 | QWK ≥ measured human–human QWK on the same Tier-1 responses, compared by a **paired** bootstrap on the difference |
| Levels 8–12 marks | QWK ≥0.75 · within ±1 ≥85% · AO-level agreement ≥80% · within-band mark agreement ≥70% on any AO whose band is ≥4 marks wide | same |
| Levels 20–30 marks | QWK ≥0.70 · within ±2 ≥85% · AO4-level agreement ≥80% · within-band mark agreement ≥70% on any AO whose band is ≥4 marks wide | same |
| All | rationale validity ≥95% (human audit: every credited span real and correctly read) · signed error within ±0.3 per 10 marks · run-to-run identical total ≥95% and identical level 100% on the reproducibility run (05-PIPE-006a) · fairness rule below | |

**Both conditions are gated on the lower bound, not the point estimate.** A family QWK computed on 50 responses has a bootstrap 95% CI of roughly ±0.15; a gate on the point estimate would pass and fail at random. Condition (a) is met when `QWK_lo` (the lower bound of the bootstrap 95% CI) clears the floor; condition (b) is met when the lower bound of the paired bootstrap on `(AI–human QWK − human–human QWK)` is ≥0.

**Fairness is gated at paper level (05-GATE-002b).** A deliberately balanced 200-response fairness sample per paper (region, L1, handwritten/typed, length tercile) is drawn separately from the family gold sets. A bucket fails when the **upper bound** of the bootstrap 95% CI for `(overall QWK − bucket QWK)` exceeds 0.10, evaluated at n ≥ 100 per bucket. Below n = 100 the bucket is reported "insufficient n" on the calibration page — the row is shown, never omitted — and the paper may not claim a fairness result for it. Family-level fairness is monitoring only. Recruit the handwritten bucket first: it is the one with a mechanism for bias (OCR).

Three states, not two: **gated** (both conditions met), **provisional** (floor met, human line *not yet measured* — every Mark carries the provisional badge), **n/a** (human line *not applicable*, exact-match papers only — gated without a badge). Ofqual's 0.52–0.96 figures are grade probabilities, not QWK; they justify measuring our own line, never lowering the floor.

```python
def predicted_grade(course, attempts_by_paper, thresholds, pack):    # thresholds: last ≥3 series per component
    if not pack.syllabus.pum_verified:                                # 05-PRED-008: no constants in code
        raise PumUnverified(course.syllabus_code)                     # the panel renders "not yet available", never a number
    pum_map = pack.syllabus.pum_map                                   # {A*: 90, A: 80, …} read from the official PUM guide
    per_paper = {}
    for paper in course.papers:
        raw = component_estimate(attempts_by_paper[paper])            # timed, unaided, gated Marks only; recency-weighted
        pums = []
        for series in thresholds[paper][-3:]:
            grade_floor = series.grade_at(raw)                        # A–E (no A* at component level)
            pums.append(series.pum_interpolate(raw, pum_map))         # linear between adjacent grade thresholds
        per_paper[paper] = dict(raw=raw, pum_low=min(pums), pum_high=max(pums), marks_to_next=series.next_threshold(raw) - raw)
    option_pum = weighted_mean(per_paper, course.option_weights)      # e.g. A Level 9609: each paper raw/2 of 200
    return dict(grade_range=option_grade_band(option_pum_low, option_pum_high), per_paper=per_paper, series_used=[...])
```

## 05.13 The machine-scored and IRT engine

This is the **third** engine and it is v2 (SYNTHESIS §8.12 FINAL; gated as a v2 done-condition by 00-DONE-003). Machine-scored exams — UNT, SAT, ЕГЭ Part 1, JEE, and the MCQ components of expert-marked boards such as 9708 P1/P3 and 9709's MCQ papers — are not marked by judgement at all. Their unit of truth is a key, and their unit of *meaning* is a **scaled score estimated from an item bank**, not a sum of raw marks. Everything in §05.2–§05.9 that concerns levels, AOs, evidence rules, rationale prose and the Examiner Twin is out of scope here; what replaces it is item calibration, θ estimation and error reporting.

Build it as a separate service (`engine/irt`) that shares only the Item bank, the Attempt record and the Mark envelope. Nothing in this subsection may be used to score a levels or a points-with-judgement Item, and nothing in §05.3–§05.6 may be used to produce a scaled score.

### Eligibility

| ID | Requirement |
|---|---|
| 05-IRT-001 | **Eligible item families, exhaustively.** `Item@2.item_type ∈ {mcq, numeric_exact, short_exact, match, order}` **and** the Item carries a deterministic key (`answer_key` with an accept list and, for numeric, a tolerance) **and** its scheme is `scheme_type: "points"` with every marking point machine-verifiable (exact match or SymPy recompute). Any other Item — every `levels` scheme, every `mixed` scheme, every points scheme with a judgement-bearing marking point, every practical scheme — is refused by the engine with `IrtIneligible(item_id, reason)`. *Acceptance:* feeding the 05.12(a) 20-mark essay Item to `engine/irt` raises; feeding the 05.12(b) points Item raises (`AN1–AN3` are judgement-bearing). |
| 05-IRT-002 | **No `per_ao` object is ever emitted for an IRT Item**, and no IRT Item ever produces a `total_band` with a `tolerance` derived from `scheme.tolerance`. The Mark envelope for an IRT Item is `per_point[]` (05-MARK-013) with `glyph ∈ {✓, ×, Ø}` only, plus one additional block `theta` (05-IRT-007). `total_band.exact = true` on every scored IRT Item, because every point is deterministically verified (05-MARK-016). *Acceptance:* schema test asserts `per_ao == null ∧ theta != null` on IRT Marks and the converse on every §05.2 Mark. |
| 05-IRT-003 | **Feedback without prose.** An IRT Item has no student text to quote, so 05-SCOP-005 (every credited point quotes a span) does not apply and is not weakened for anything else. The feedback layer is the **distractor-to-misconception map**: each wrong option carries `misconception_id` from the Pack (§06.3 `syllabus_nodes[].misconceptions`), and the Mark renders one sentence naming the misconception and one contrast-pair Item, never "incorrect". An option with no `misconception_id` renders the syllabus-point name only. *Acceptance:* every scored `mcq` Item in a `gated` Pack has a `misconception_id` on ≥ (k−1) of its distractors, or it is `trial` (05-IRT-009). |

### Item-bank calibration

| ID | Requirement |
|---|---|
| 05-IRT-004 | **Model and estimation.** Default **2PL** (discrimination `irt_a`, difficulty `irt_b`); **3PL** (adding the pseudo-guessing asymptote `irt_c`) only where the item is `mcq` with a fixed option count, with `irt_c` bounded to `[0, 1/k + 0.05]` and a Bayesian prior, never estimated free. Calibration is marginal maximum likelihood over the response matrix, re-run nightly per Pack. `Item@2` gains `{irt_model ∈ {none, 2pl, 3pl}, irt_a, irt_b, irt_c, irt_se_a, irt_se_b, calibration_n, calibration_at, fit, exposure_rate, trial_status}`. **Why:** a 3PL fitted free on a few hundred responses puts most of its uncertainty in `c` and produces difficulty estimates that move with the sample; a bounded prior is the standard operational compromise. |
| 05-IRT-005 | **Calibration volume, staged.** `calibration_n < 300` → the item is `trial_status: trial` and contributes nothing to θ. `300 ≤ calibration_n < 500` → `trial_status: provisional`; the item scores, but the paper cannot leave `provisional` on its 05-GATE-002 row. `calibration_n ≥ 500` on a sample spanning at least two ability terciles → `trial_status: live`. | 05-IRT-006 | **Item-fit statistics and retirement.** Per item, computed at every nightly calibration: weighted (infit) and unweighted (outfit) mean-square, required in **0.7–1.3**; point-biserial correlation ≥0.20; `irt_a` in `[0.4, 2.5]`; and **DIF** by the same buckets as 05-GATE-002b (region, L1, handwritten/typed where applicable) using Mantel–Haenszel with the ETS A/B/C classification at n ≥ 200 per focal group. An item outside any bound, or classified **C** on DIF, is moved to `trial_status: retired` within one nightly run: it stops being served, its prior responses stay in the bank for linking, and the scores it already contributed to are recomputed and the affected students told (05-IRT-011). ### θ, standard error and what the student sees

| ID | Requirement |
|---|---|
| 05-IRT-007 | **θ estimation.** Expected a-posteriori (EAP) with a standard normal prior over the item responses in the scored set; the Mark carries `theta {value, se, n_items, items_live, items_provisional, method: "eap", prior: "n(0,1)"}`. The reported score is `scale(θ)` from `pack.syllabus.score_scale` — Pack data with `source_url` and `scale_verified`, exactly like `pum_map` (05-PRED-005) — and is **always** rendered as a range `scale(θ − 1.96·SE) … scale(θ + 1.96·SE)`, never a point, with the fixed line "Your practice estimate is a range because {n_items} items measure you this precisely." A Pack with `scale_verified: false` renders the missing-input line and no number, on the same rule as 05-PRED-008. |
| 05-IRT-008 | **Two error gates, both blocking.** (a) **θ standard error:** `SE(θ) ≤ 0.30` at the ability region containing the paper's own cut scores, measured on the calibration sample; a paper whose test information cannot reach that at its published length publishes no score estimate and shows per-topic diagnostics only. (b) **Score error:** the RMSE of `scale(θ)` against the exam's own reported scores on a linking sample of ≥200 candidates is **≤ the exam's published standard error of measurement**; where the exam publishes no SEM, the gate is RMSE ≤ 4% of the scale range and the calibration page says which rule was used. Both are computed on the lower/upper bound of a bootstrap 95% CI in the conservative direction, as in 05-GATE-002. |
| 05-IRT-009 | **Exposure control and trial seeding.** Every delivered set draws 2–5% of its items from `trial_status: trial`, unscored and indistinguishable to the student, which is how `calibration_n` accumulates; trial items are excluded from θ, from the score range and from any streak or mastery write. Live-item exposure is capped by a randomesque rule (draw from the top 6 by information at the current θ, uniformly) with a per-item exposure rate ≤0.25 across the paper's active cohort in any 30 days; an item over the cap is rested. **Why:** an item bank that always serves its most informative item is memorised and copied within one series, and the first thing that leaks is the gate. |
| 05-IRT-010 | **Item security.** Live IRT items are never rendered in an offline bundle (11-OFF-001), never exported into a Receipt or a Card back, never included in a share link, and never regenerated by the §05.10 generator from a live item's parameters. | 05-IRT-011 | **Recomputation is announced, never silent.** When an item retires (05-IRT-006) or a Pack re-calibration moves any `irt_b` by more than 0.3 logits, every affected score estimate is recomputed and the student sees one line on the Progress paper panel: "Your estimate moved from {old} to {new} — we retired {n} question(s) that were not measuring what they should." No estimate is changed without that line, and the previous estimate stays in the history. |

# §06 The library: content, curriculum packs, licensing

## 06.1 The three-provenance content model

Every byte of content Margin retrieves, displays, marks against or exports belongs to exactly one of three provenance classes. The class is a column, not a convention: it is set at ingest, carried on every `documents`, `chunks`, `items`, `mark_schemes` and `examiner_insights` row (§11.2), checked by the retrieval prefilter (11-RAG-003) and by the render layer, and audited in the `provenance_ledger`. There is no fourth class. A document that cannot be assigned one of the three is not ingested.

### Definitions

| Class | Definition (exact) | Examples | May be pooled into global retrieval | May display text | May be exported (Receipts, Cards, print) |
|---|---|---|---|---|---|
| `OWN` | Content authored by Margin staff, contractors or generators under our own copyright: original Items and stimuli (05-GEN), our paraphrased scheme wording (`wording_status=own_paraphrase`), `examiner_insights.text`, syllabus-graph nodes we wrote, facts extracted from public documents (syllabus statements, paper structures, AO weights, thresholds), page/question anchors that point at official PDFs. | `itm_01JXA4W2K9Q7ZB3M6N8VYT1CDE` (ULID; the slug `it_9609_5.3_0412` is not an id and never appears in data), `ms_9609_41_MJ25_Q1@3` (paraphrase), `ei_9609_m25_004`, `syl_9609_2026#2.2.1` | Yes | Yes | Yes |
| `LICENSED` | Third-party text or images held under a written agreement recorded as a `licences` row with `licence_id, licensor, scope, territories[], display_rights ∈ {grounding_only, extracts, full_text}, expiry, max_quote_words`. Nothing is `LICENSED` until counsel has filed the signed instrument and its `licence_id` exists. | Endorsed coursebook chapters under a Cambridge University Press & Assessment or CLA agreement; verbatim grid wording if Cambridge grants it (`wording_status=licensed_verbatim`). | Yes, only within `scope.syllabus_codes[]` and `territories[]` | Per `display_rights` | Only if `scope.export=true` |
| `USER` | Files a student, teacher or school uploads: past papers, mark schemes, examiner reports, School Support Hub material, textbook photos, notes (including the founder-supplied ZNotes text until a ZNotes agreement exists, SYNTHESIS §9). Processed for the uploading principal only; the `partition_key` is the uploader's tenant (or the user id for individuals); retention per `uploads.retention_until`. | `upl_01JX…` (9609 s24 P4 mark scheme photographed by a teacher), the founder's mechanisms file (`licence_basis="user"` in 05.3) | **Never** | Yes, to the owning principal only | Only to the owning principal, never in a shared artefact |

`licence_basis` on the ledger refines the class: `own`, `licensed:<licence_id>`, `user`, `public_with_permission:<permission_ref>`, `quotation`. `public_with_permission` is a sub-case of `LICENSED` (a written permission is a licence); a public URL alone is never a basis. **Why:** UK law offers no commercial TDM exception (March 2026 report) and Cambridge refuses electronic republication of questions, schemes and ERs; a "we found it online" class would be the exact thing a takedown targets (GL §A1, §A4).

**`quotation` is a basis, not a class.** Every short attributed extract — the 18 verbatim command-word definitions per Pack and every ≤40-word quotation under 06-STOR-001 — is recorded as `licence_basis: quotation` with a mandatory sub-object `{exception ∈ {uk_cdpa_s30, us_fair_use, eu_art5_quotation, other}, jurisdiction, reviewed_by, reviewed_at}`. It never becomes a fourth provenance class and it is never recorded as `own`, which would be false and would make 06-TAKE-021's per-document report unanswerable for exactly the content most likely to be complained about. *Acceptance:* every row in `extract_log` resolves to a document whose `licence_basis ∈ {licensed:<id>, public_with_permission:<ref>, quotation}`; a `quotation` row with no `exception` fails ingest.

**Provenance stays at three members; every other state is a sibling column.** The three-value enum is enforced by 06-PROV-001, so refinements are never smuggled into it with an arrow or a hyphen. The siblings are: `consent_status ∈ {none, gold_consented}` on exemplars (a consented Tier-1 script is `provenance: USER` with `consent_status: gold_consented`, never `USER→gold_consented`); `text_status ∈ {own, own_facts, licensed, ref_only}` on documents, where `own_facts` is our restatement of uncopyrightable facts from a third-party document; `licence_basis` as above; and `links[].derivation` (06-PACK-006) for how a graph edge was produced. *Acceptance:* a repo lint rejects any provenance literal containing `→`, `-` or `:`.

### Requirements

| ID | Requirement |
|---|---|
| 06-PROV-001 | `provenance ∈ {OWN, LICENSED, USER}` is a `NOT NULL` enum on `documents`, `chunks`, `items`, `mark_schemes`, `examiner_insights`, `textbook_sections`, `figures`, `exemplars`. A migration adding a fourth value fails CI (schema lint asserts the enum has exactly three members). *Acceptance:* `INSERT … provenance='scraped'` raises; the enum test is in the migration suite. |
| 06-PROV-002 | **Retrieval never mixes tenants' USER content.** Every retrieval call names its partitions explicitly: `['global']` plus at most one tenant partition, equal to the caller's `org_id` (or `user:<id>` for individuals). Two tenant partitions in one query is a request-validation error, not a filtered result. *Acceptance:* the isolation suite (11-DATA-004) runs 10,000 randomised queries across 50 synthetic tenants and returns 0 cross-tenant chunks; a query naming two tenant partitions returns HTTP 400. |
| 06-PROV-003 | **USER content is never embedded into the global partition** and never used to build OWN artefacts that quote it. Generators (05-GEN), Card builders (§04) and the compiler may *read* a tenant's USER chunk only inside that tenant's job; any OWN row they emit must pass 05-GEN-005's near-duplicate check against USER text as well as official text. *Acceptance:* a fixture uploads a unique 40-word paragraph as USER; no OWN row created in the following 24 h contains an 8-gram of it. |
| 06-PROV-004 | **LICENSED served only where scope allows.** The prefilter joins `licences` and drops chunks where `now() > expiry`, `caller.residency ∉ territories`, `course.syllabus_code ∉ scope.syllabus_codes`, or the requested rendering exceeds `display_rights`. A chunk allowed for grounding but not display reaches the model with `render=false` and can be cited but never quoted (06.6). *Acceptance:* flipping a licence's `expiry` to yesterday removes its chunks from the next query with no deploy; a `grounding_only` chunk quoted verbatim fails the post-lint (05-PIPE-009 extends to Learn Turns). |
| 06-PROV-005 | Every OWN paraphrase records what it paraphrases: `source_ref {document_id, page, bbox?}` pointing at the official PDF's location, so the citation chip can deep-link (06.6) without holding the text. A paraphrase row without `source_ref` is a lint error unless `kind=original_item`. |
| 06-PROV-006 | Class is immutable per document version. Re-classifying (e.g. USER → LICENSED when the ZNotes agreement lands) is a **new** `doc_id` ingested from the licensed copy, with the old USER copies untouched. **Why:** a licence covers a specific file the licensor supplied, not whatever a user photographed. |
| 06-PROV-007 | The kill switch (06.10) applies to all three classes identically: `provenance_ledger.kill_switch=true` removes the document's chunks from the prefilter, its `items` from practice selection, its rows from any Pack build and its extracts from caches within the SLA. |

### Provenance ledger entry

Append-only; one row per document version; every row signed into the daily audit hash chain (§12). The block below lists the **shape** — `a | b | c` enumerates the legal values of a field, it is not a value — so it is skipped by the instance validator (06-PACK-001).

```yaml
provenance_ledger:
  ledger_id: pl_01JXQ7…                 # ULID
  doc_id: doc_9609_syl_2026             # stable across versions; version below
  doc_version: 3
  provenance: OWN | LICENSED | USER
  licence_basis: own | licensed:lic_cupa_2027_01 | user | public_with_permission:perm_cb_2026_11 | quotation
  quotation_basis: {exception: uk_cdpa_s30, jurisdiction: GB, reviewed_by: counsel_01, reviewed_at: 2026-10-01} | null   # required iff licence_basis = quotation
  licence_id: lic_cupa_2027_01 | null
  source_url: https://www.cambridgeinternational.org/Images/697371-2026-2028-syllabus.pdf | null   # official page for facts/anchors; null for USER
  sha256: "9f1c…e2"                     # of the ingested bytes
  bytes: 2481773
  ingested_at: 2026-10-03T14:02:11Z
  ingested_by: user_id | job_id
  uploader_org_id: org_… | null         # USER only; equals partition_key
  partition_key: global | org_01… | user_01…
  expiry: 2028-08-31 | null             # licence end; AQA 3-year public window; Pearson 5-year; USER retention_until
  display_rights: full_text | extracts | grounding_only | anchors_only
  text_status: own | own_facts | licensed | ref_only
  trust_rank: 1..6
  kill_switch: false
  takedown: {requested_at: null, requester: null, notice_id: null, removed_at: null, reinstated_at: null}
  derived_from: [doc_id@version, …]     # OWN paraphrases list their official sources
  checksum_prev: "…"                    # hash chain
```

| ID | Requirement |
|---|---|
| 06-PROV-008 | `source_url` is mandatory for `OWN` rows with `derived_from ≠ []` and for `LICENSED`; `sha256` mandatory for all; `uploader_org_id` mandatory for USER. Rows are never updated except `kill_switch`, `takedown.*` and `expiry` (extension by a new licence version). *Acceptance:* trigger rejects any other `UPDATE`; hash chain verifies nightly. |
| 06-PROV-009 | The ledger is queryable by the takedown desk in ≤1 s by `sha256`, `source_url`, `doc_id` or free text over titles; the answer lists every chunk, item, scheme, insight and cache key derived from the document (via `derived_from` closure). |

### Tests the class model must pass before any Pack is `live`

1. **Class purity:** a SQL assertion that no chunk in `partition_key='global'` has `provenance='USER'` (run on every ingest batch and nightly).
2. **Scope fence:** for each `licence_id`, sample 200 queries from a tenant outside `territories` — 0 chunks returned.
3. **Ref-only fence:** for every `documents.text_status='ref_only'` row, `chunks.text` is empty and only `{page, bbox, question_ref}` anchors exist (11-RAG-004).
4. **Derivation closure:** killing a random official document removes 100% of the insights and paraphrases whose `derived_from` includes it (06.10).
5. **Founder library check:** the twelve ZNotes-derived files and the mechanisms file from the corpus sample are classified USER under the founder's org, `trust_rank=5` (revision notes) or `6` (hand-compiled scheme extracts, rising to `3` per record once a human confirms the transcription against the official scheme in 06.7 — the 05.3 example shows the confirmed state), and none of their text appears in `global`.

## 06.2 What is stored, what is displayed, what is deep-linked

This subsection is the storage-and-display matrix the render layer, the cache and the compiler all read from. Three verbs are distinct in code: **store** (bytes in our object storage or text in `chunks.text`), **display** (text or image painted in a Margin surface), **deep-link** (a chip or button that opens the rights-holder's own page in a new tab or the in-app browser). A document may be stored for grounding and not displayed; a document may be deep-linked and never stored.

### The matrix

| Content | Store | Display | Deep-link | Class / basis | Notes |
|---|---|---|---|---|---|
| Syllabus **facts**: codes, paper structure, durations, marks, AO weights, topic numbering, learning-objective statements restated, command-word list | Yes (OWN facts, `derived_from` the syllabus PDF) | Yes | Yes, to the official syllabus PDF `#page=` | OWN | Facts are not copyright; keep wording ours except the command-word *definitions*, which are stored verbatim as short quotations under the extract rule (needed for 05-PROC-012). |
| Command-word definitions (verbatim) | Yes, ≤40 words each | One at a time, in the detail popover only, as an attributed quotation with chip; lists and tables render the paraphrase (06-STOR-010) | Yes | OWN, `licence_basis: quotation` | 18 definitions × ≤40 words. Storage is logged once per Pack build; **display** is per view and capped by 06-STOR-010. |
| Official board PDFs: past papers, mark schemes, examiner reports, specimen papers, ECRs | **Never re-hosted.** Store only: `sha256`, page count, per-question page anchors `{question_ref, page, bbox}`, our OWN paraphrases and insights. `chunks.text` empty (`text_status=ref_only`). | Never (no viewer) | Yes, to the exact official URL when public; "Open on School Support Hub" when SSH-only | OWN anchors; the PDF itself is not held | Cambridge refuses electronic publication of questions, schemes and ERs (GL §A1). The Paper Companion anchors feedback to question numbers on the student's own copy. |
| Grade-threshold tables | Yes, as numbers (`thresholds`, `option_thresholds`) | Yes | Yes, to the thresholds PDF | OWN facts | 05-PRED-005. |
| Short attributed extracts from any board or publisher document | Yes, the extract text only, inside the OWN row that cites it (`extract_text`, `extract_words`) | Yes, quoted, with chip | Mandatory alongside | OWN, `licence_basis: quotation` | Limits below. |
| Endorsed textbook pages | Only under a `licence_id` with `display_rights ≥ extracts`; stored as `textbook_sections` + chunks in `global` | Per `display_rights` | Yes, to the publisher's product page or licensed reader URL | LICENSED | Without a licence: not stored, not displayed; a student may upload their own copy (USER). |
| Revision notes (ZNotes and similar) | Global only under a licence; otherwise USER | USER: to owner only | Yes, to the publisher's page | LICENSED or USER | SYNTHESIS §9: ZNotes is USER until an agreement exists. |
| User uploads (papers, schemes, ERs, SSH material, notes, photos of textbook pages) | Yes, tenant partition, encrypted at rest, `retention_until` | Owner only; teacher-of-record sees a student's upload only when attached to an Attempt in a `receipt_required` assignment | n/a | USER | Retention is `config/retention.yaml` (§07.8 defaults, 11-PRIV-004 ceilings), never a number stated here (06-STOR-005); deletable any time, deletion propagates to chunks and caches ≤24 h. |
| Handwritten answer images | Yes, per 05-HAND-008 | Owner + teacher of record | n/a | USER | Never training data. |
| Our original items, stimuli, schemes, insights, model answers | Yes | Yes | Chip to the *source* they were derived from where applicable | OWN | Rendered with "Original item · in the style of …" (05-GEN-009). |

### Extract limits (enforced, not advisory)

| ID | Requirement |
|---|---|
| 06-STOR-001 | An **extract** is verbatim text from a non-OWN, non-`full_text` source. Hard caps per extract: **≤40 words and ≤2 sentences**; per Turn or Mark: **≤3 extracts, ≤100 words total**; per Session: **≤12 extracts**; per document per user per day: **≤10% of the document's pages may be touched by extracts** (page count from the ledger). A licence with `max_quote_words` overrides the per-extract cap in either direction. *Acceptance:* the post-lint counts words of every quoted span against the source chunk; a 41-word quotation fails the Turn and regenerates with the cap named. |
| 06-STOR-002 | **Grid and marking-point wording is never displayed verbatim** without `wording_status=licensed_verbatim`, regardless of length. The Mark shows `descriptor_relied_on.paraphrase` and a chip to the page (05-MARK, 05-PIPE-009). *Acceptance:* the 300 gold Marks contain 0 sentences with ≥8-gram overlap with the ingested official scheme text. |
| 06-STOR-003 | Every displayed extract is **attributed inline** in the fixed form `"…quoted text…" — {Board}, {syllabus code}/{component} {series}, {document type}, p.{page}` with a chip that deep-links (06.6). An extract without a resolvable chip is not rendered; the sentence falls back to paraphrase. |
| 06-STOR-004 | Extracts are **audit-logged**: `{user_id, org_id, doc_id, page, chunk_id, words, surface, turn_id | mark_id, at}` to `extract_log`, retained 3 years, exportable per document for a licensor or a takedown response. |
| 06-STOR-005 | **User uploads are transient and private.** §06 states **no retention number**: `uploads.retention_until` is computed from the retention table §07.8 renders and the platform ceilings 11-PRIV-004 sets, both of which read `config/retention.yaml`; a transient upload is short-lived and an upload saved to a Course lives as long as the Course. A number for uploads written anywhere in §06 is a docs-lint failure. What §06 owns is the **propagation**: a student's "Delete this file", and expiry of `retention_until`, remove the object, chunks, figure crops, derived Cards' source text (Cards keep the student's own wording) and cache entries within 24 h, and write the ledger `takedown.removed_at`. Uploads never enter `global`, never train anything, never appear in another user's citations. *Acceptance:* delete → query → 0 chunks within 24 h; nightly job proves no `USER` row in `global`; the docs lint finds no duration literal in §06. |
| 06-STOR-006 | The **Papers surface** and the Paper Companion open official PDFs by deep link in the in-app browser; Margin never proxies, caches or screenshots the PDF bytes server-side. For SSH-only material the surface shows the teacher-upload path and the string "Your school can download this from the School Support Hub." |

### Caching rules

| ID | Requirement |
|---|---|
| 06-STOR-007 | Prompt caches (§08) may contain LICENSED text only for tenants inside the licence's territory, keyed with `licence_id` and `residency`; they may contain USER text only in a cache key that includes `org_id` (or `user_id`), TTL ≤1 h. OWN text caches freely. A kill switch or licence expiry invalidates every cache key that lists the `doc_id` in its manifest (06.10). |
| 06-STOR-008 | Client-side and CDN caches never receive extract text or LICENSED text as static assets; they are rendered inside authenticated Turn/Mark payloads only. Offline (11-OFF-001) may store OWN documents and LICENSED documents whose licence has `offline=true`; never USER documents belonging to another principal. |
| 06-STOR-009 | Reference index for the near-duplicate check (05-GEN-005) stores **hashes and vectors, never displayable text**, for official and USER text alike; that index is exempt from extract caps because nothing in it can be rendered. |
| 06-STOR-010 | **The command-word table is displayed as paraphrase; the verbatim definitions are displayed one at a time.** Storing the 18 verbatim definitions once per Pack build (06.2) is a storage decision and does not license a permanent, complete, verbatim reproduction of a board's command-word table to every user. In-product, `command_words[].definition_display` — our OWN paraphrase — is what any list, table, glossary, onboarding sheet or Pack page renders. The verbatim string appears only in the **command-word detail popover**, one word at a time, attributed, chip-linked and logged per view against the extract budget (06-STOR-001, 06-STOR-004). No surface renders more than **three** verbatim definitions in one view, and no surface renders the table verbatim at all. `mark@`'s static prefix is unaffected: the marker receives the verbatim definition for the one command word it is marking (05-PIPE-002), which is not a display. *Acceptance:* a crawl of every product route counts verbatim `definition` strings per view and fails above three; the glossary route renders zero. Whole-table reproduction is on the counsel question list (15-OPEN-040). |
| 06-STOR-011 | **What a logged-out surface may render.** The public past-paper finder (§14.4) and any other unauthenticated route serve **anchors and metadata only**: board, syllabus code, subject, series, component, paper and mark-scheme titles, page counts, and the official deep link (06-CITE-004). Zero extracts, zero question text, zero scheme or examiner-report text, zero OWN Items, zero USER content, and no citation chip whose `display_rights` is above `anchors_only`. The non-affiliation notice (06-NONA-002) and the mirror-domain blocklist (06-CITE-006) apply unchanged. Logged-out requests carry `principal: anonymous` and the retrieval prefilter names the single partition `['global']` with `display_rights = anchors_only` forced, so the rule is enforced by the same code path as every other request rather than by the page. *Acceptance:* a crawl of every logged-out route asserts zero `extract` fields in any payload and zero chunks with non-empty `text`; a fixture request forging a tenant partition while unauthenticated returns HTTP 400 (06-PROV-002). |

### Per-region variations

| Region (tenant `residency`) | Variation |
|---|---|
| UK | Quotation exception (CDPA s.30) is the legal basis for extracts; caps above apply; no commercial TDM exception, so no crawling. Board public windows honoured as `expiry`: AQA 3 years, Pearson 5 years — after expiry, anchors only. |
| EU | Same caps; DSM Art. 4 opt-outs mean no crawling of board sites; LICENSED chunks served only if `territories` includes EU; residency routing per §11 keeps LICENSED and USER text on EU endpoints. |
| US | College Board FRQs and scoring guidelines are publicly posted; still `ref_only` until a permission is filed; extracts allowed under the same caps (fair-use posture); *Thomson Reuters v. Ross* argues against systematic display of editorial scheme text, so the caps are not loosened. |
| Kazakhstan / Russia / rest of world | Same product rules; regional pricing does not change content rights. DeepSeek never sees USER or LICENSED text [E5], and — because it carries no contractual no-training assertion (§08.11) — it never sees **Pack-derived OWN text** either: no `mark_scheme_items`, no `examiner_insights`, no generated Items, no grids. Its permitted payloads are public question stimuli and the numeric pre-solve task. **Why:** the structured scheme layer and the insight corpus are the assets a competitor cannot buy; routing them to an untrained-on-what-basis provider trades the moat for a batch discount. The route-level enforcement is 08-POL-011's. |

**Why:** the four-pattern analysis (GL §A4) rates transient user processing strongest, short attributed extracts weak-but-defensible, and server-side hosting of board PDFs indefensible without a licence; the matrix encodes exactly that ordering.

## 06.3 The curriculum Pack schema

A Pack is the complete curriculum dataset for one syllabus version, serialised as one versioned document tree in Postgres (Pack plane, `org_id NULL`, §11.2) and exportable as a single YAML bundle for review, diff and CI. Every Mark pins `pack_version` (05.2 header); every Course pins it (11-DATA-005). Below is the canonical bundle. Tables named in F§7.1 and §11.2 are the storage form; this is the logical form the compiler emits and the eval harness consumes.

## 06.4 The Curriculum Compiler pipeline

The Curriculum Compiler is the internal DAG (worker service `ingest`, §11.1) that turns a pile of messy PDFs into a versioned Pack. It is internal from month 1 (SYNTHESIS §9: v0 produces 0450 and 9708 from the 9609 grid engine; the public "any syllabus PDF" compiler is LATER). It runs on **PDFs, never text dumps** — the founder's text extracts (corpus-sample §2) are evidence of what goes wrong, not input.

```
 0 Intake ─► 1 Classify ─► 2 Parse (Docling) ─► 3 VLM page audit ─► 4 Figures & tables ─► 5 Maths OCR
   ─► 6 Per-source cleaning ─► 7 Dedupe ─► 8 Section→syllabus mapping [review UI] ─► 9 Paper-ID normaliser
   ─► 10 Question↔scheme alignment [review UI] ─► 11 Scheme structuring (06.7) [human confirm]
   ─► 12 Examiner-report mining [review UI] ─► 13 Graph build ─► 14 QA sampling ─► 15 Gold seed & gate (05.6) ─► 16 Publish
```

## 06.5 Trust ranks and notes-vs-canon behaviour

Trust rank orders sources when they disagree or tie in retrieval; it never overrides the hard rule that marking uses only a `mark_scheme_items` record (05-SCOP-002). The ranks are FINAL in SYNTHESIS §3.1/§9 and are already used by the 05.2 `sources[]` array (`trust_rank: 3` for a scheme, `4` for an ER). Do not reorder them per subject or per tenant.

### Rank table

| Rank | Source kind | Typical class | What it is authoritative for | What it is not authoritative for |
|---|---|---|---|---|
| 1 | Syllabus (current version window) | OWN facts + verbatim command words | What is examinable, official numbering, command-word meaning, AO weights, paper structure, units and conventions the syllabus states | How a specific question was marked |
| 2 | Endorsed textbook (board-endorsed coursebook) | LICENSED (or USER when the student uploads a page) | Explanations, definitions, worked examples, diagrams | Marking of a specific question; anything post-dating its edition |
| 3 | Mark scheme (official) | OWN paraphrase + anchors; USER when uploaded | The creditable points and level descriptors for that question part; accept/reject lists | General theory beyond that question; other series' wording |
| 4 | Examiner report | OWN insights + anchors; USER when uploaded | What scored and what did not in that series; recurring errors; examiner phrasing of advice | Definitions; the current syllabus content if the series predates it |
| 5 | Revision notes (licensed notes, ZNotes-class community notes) | LICENSED or USER | Compact restatements, lists, mnemonics | Facts when they conflict with 1–4; numbering |
| 6 | User upload of unknown type; the student's own notes; hand-compiled extracts before confirmation | USER | The student's own record of what they were taught | Anything, when it conflicts with 1–5 |

Within rank 5, `sub_rank` separates `licensed_notes (5.0)` from `community_notes (5.5)`; within rank 6, a hand-compiled scheme extract rises to rank 3 per record once a human confirms it against the official scheme (06.7). A brief elsewhere proposes syllabus > mark scheme > examiner report > textbook; reject it here — for **explaining**, an endorsed textbook is more reliable than a scheme written for one question; for **marking**, rank is irrelevant because only the scheme record counts.

| ID | Requirement |
|---|---|
| 06-TRUST-001 | Retrieval (11-RAG-003) filters by `syllabus_code` and `syllabus_version` **before** similarity; `trust_rank` breaks ties after reranking and boosts by `+0.02 × (6 − trust_rank)` on the fused score, never more. **Why:** a rank-5 chunk that answers the question beats a rank-1 chunk that does not; trust is a tie-breaker, not a filter. |
| 06-TRUST-002 | A **stale-version penalty** applies before trust: a chunk from a superseded syllabus version or a pre-version ER is retrievable only when no current-version chunk covers the node, and is then labelled "from the 2023–25 syllabus — check it is still examinable". |
| 06-TRUST-003 | **Conflict detection** runs on the assembled top-8 (11-RAG-006): when two chunks on the same node state different values for the same quantity, unit, definition, date, name or list membership, and their ranks differ, the orchestrator emits a `conflict` part before the answer. ### How the tutor speaks when notes disagree with canon (exact strings)

The `conflict` part renders as a card above the Turn (§09 conflict card). Strings below are fixed; `{…}` fields are filled; no other phrasing is permitted (microcopy lint, §15.E).

```
CONFLICT CARD — title:      "Your notes and the syllabus disagree"
line 1 (lower rank):        "Your notes: {value_low}  · {source_low_label}, p.{page}"
line 2 (higher rank):       "{source_high_label}: {value_high}  · {citation_high}"
footer:                     "I'll use the {source_high_label} version. Tap either source to see the page."
```

Worked instances:

```
Your notes and the syllabus disagree
Your notes: standard temperature 273 °C  · ZNotes 9701 theory, p.12
Syllabus: standard temperature 273 K  · Cambridge 9701 syllabus 2025–27, §3.1
I'll use the Syllabus version. Tap either source to see the page.
```

```
Your notes and the examiner report disagree
Your notes: "repeat the business name to show application"  · your upload, p.3
Examiner report: application needs a fact true only of this business  · 9609 Principal Examiner Report, March 2025, Paper 4
I'll use the Examiner report version. Tap either source to see the page.
```

In-Turn sentence (when the conflict is minor enough not to warrant a card, e.g. spelling of a researcher's name): `"Your notes spell it 'Pilivan'; the textbook and the syllabus use 'Piliavin' — I'll use that."` The pattern is fixed: `"Your notes {say|spell|list} {X}; the {source_high_label} {says|spells|lists} {Y} — I'll use that."`

When two canon sources disagree (rank 1 vs 3, e.g. a scheme accepts a definition the syllabus words differently): `"The mark scheme for {question_ref} accepted {Y}; the syllabus wording is {X}. Either earns the mark on that question; learn the syllabus wording."`

When a user asks the tutor to prefer their notes: `"I can explain your notes' version, but I mark against the syllabus and the scheme, so I'll flag where they differ."` The tutor never adopts a rank-5/6 fact as ground truth in a Mark or a Card back.

## 06.7 The paste-to-structured marking-point tool

The founder's mechanisms file (corpus-sample §4.3) is the highest-value asset in the sample: question → official marking points. This tool makes producing such records faster than typing prose. It is an internal/teacher screen (compiler stage 11 in batch; teacher console at calibrator scope for their own uploads, §10) that turns pasted or OCR'd scheme text into a 05.3 `mark_scheme_items` record in our wording, with a mandatory human confirm.

### Flow

```
paste / select text on an uploaded page ─► 1 detect scheme_type & part ─► 2 LLM proposal (05.3 JSON, own wording)
  ─► 3 deterministic validation ─► 4 confirm UI (source crop | proposed record; atoms editable) ─► 5 save @version, provenance
```

Input example (pasted from the founder's file):

```
S15 variant 21 — nucleophilic addition of CN− to a carbonyl
M1 = lone pair AND curly arrow from lone pair to carbonyl C
M2 = partial charges on C=O AND curly arrow from bond (=) to O−
M3 = structure of intermediate including charge
M4 = lone pair AND two correct curly arrows (from lone pair to H AND from H-C to C)
M5 = CN−
```

Output: the 05.3 record `ms_9701_21_MJ15_Q4b@1` already shown in 05.3 — `M1…M3` as type `B`, `M4` as `DB` depending on `M3`, `M5` with an `alternatives[]` entry, `diagram_required=true`, `vision_status=provisional_teacher_confirm`, `source.licence_basis=user`, `trust_rank` 6 → 3 on confirm.

### Prompt outline (Sonnet 5, structured output against `MarkScheme@3`)

```
SYSTEM: You convert examiner mark-scheme text into a structured record. Rules:
 1. Output only the JSON schema provided. No prose.
 2. Rewrite every credit_text in your own words; never copy a sentence of ≥8 consecutive source words.
 3. Split every "AND" / "and" that joins two checkable features into separate conjunctive_conditions; set all_required=true.
 4. "//" or "or" between alternatives → alternatives[] (credited once). "ORA" → ora=true. "cao" → cao=true. "ecf"/"ft"/"own value" → ecf_allowed=true and the point type FT or A with depends_on.
 5. "dep"/"*" markers → type DM or DB with depends_on set to the referenced point.
 6. Tag each point with an AO using the syllabus AO table supplied in context; if uncertain, ao=null and add a note.
 7. If the text is a levels grid, emit levels[] with every band, including a range [0,0] band when the grid defines it, and an evidence_rule per band in countable terms.
 8. Keep accept / reject / ignore lists as atoms. Preserve chemistry/maths notation as LaTeX.
 9. Anything you cannot classify goes in notes, never silently dropped.
CONTEXT: {syllabus AO table (OWN)}, {command-word table}, {question_id, part, marks_total from the normaliser}, {any existing record @n for diff}
USER: {pasted text}
```

**Why not demand-first:** the highest-search-volume CAIE subjects are Maths and Business, which this order already covers at positions 1 and 4; the next tranche by demand (English, Psychology) is precisely the tranche whose marking we cannot yet defend, and shipping a lenient marker on them would spend the calibration moat (SYNTHESIS §12) to win a month of traffic.

## 06.9 Licensing strategy

The product ships without a single licence (06.1 Tier 0 + Tier 1) and treats every licence as an **upgrade that flips a flag**, never as a dependency. Open the conversations in month 1 anyway: the asymmetry is that a refusal costs a letter and a licence converts the main legal risk into a moat. Licensing counterparties, terms and any fee are FOUNDER-OWNED [E2]; the sequence, the asks and the in-product effects below are not.

### The five month-1 conversations, in order

| # | Counterparty | Send in | What we ask for | What we offer | If they say yes | If they say no |
|---|---|---|---|---|---|---|
| 1 | **Cambridge University Press & Assessment** (permissions, then the AI-licensing team on the Press side) | Week 1 of M1 | (a) mark schemes and examiner reports as **retrieval grounding, not display**; (b) endorsed-coursebook text for RAG with extracts; (c) written confirmation that descriptive use of "Cambridge International A Level 9609" outside the product name is acceptable | Per-document usage reporting from the `extract_log` (06-STOR-004); a per-document kill switch they can trigger (06.10); published calibration numbers per paper; no hosting of any PDF, ever; a named contact and a 24 h SLA | `LIC_MS_GROUNDING` and `LIC_ER_QUOTE` on; `wording_status` may become `licensed_verbatim` per document | Nothing changes: paraphrase + anchors + deep links (already the default) |

### The three rights tiers, and what each unlocks

| Tier | `display_rights` | What Margin may do | Default at launch |
|---|---|---|---|
| **Facts only** | `anchors_only` | Store `sha256`, page/question anchors, our OWN paraphrase and insights; deep-link the official PDF; never store or display source text | **This is the launch state for every board document.** |

**06-LIC-003** Every flag transition is a Pack event, not a deploy: turning a flag on writes a `pack.version` minor bump, re-runs the retrieval gold set and, for marking flags, re-runs the per-paper gate before any student sees the change. *Acceptance:* flipping `LIC_MS_GROUNDING` in staging without a gate re-run blocks publish.

**06-LIC-004** Every flag is revocable in one write: setting `licences.expiry` to the past removes the chunks from the next query, restores paraphrase rendering and invalidates the caches listing that `licence_id` (06-STOR-007), with no deploy and no data migration. Test this quarterly (§12 drill).

### Fallback if nothing lands

Assume it. The launch plan already is the fallback: OWN items and schemes, OWN paraphrased insights, facts and anchors, deep links, and USER uploads processed per tenant. Nothing in §04, §05 or §07 requires a licence; the only features that would improve are verbatim descriptor display and endorsed-textbook explanations, and the honest substitute for both already ships. **06-LIC-005** No roadmap item, GTM claim or investor number may be contingent on a licence that is not signed; an item that would be is filed with `deferred_to: later`. *Acceptance:* the M6 launch checklist contains zero rows whose precondition is a `licence_id`.

## 06.10 Takedown process and the per-document kill switch

The kill switch is the reason the three-provenance model is credible: a rights-holder can verify in one email that we can and do remove a document completely, in hours, from every place it reached. Build the switch before the first ingest, not after the first notice.

### Intake

| ID | Requirement | Acceptance |
|---|---|---|
| 06-TAKE-001 | Publish **one** intake address, `copyright@{brand_domain}` rendered from `config/brand.yaml` (01-NAME-001 is PROVISIONAL until clearance, and a brand-domain literal in code, copy or a signed payload is a lint failure), plus a web form at `/legal/notice` and a named agent with a postal address, on the footer of every public page, the Papers surface, the legal page and the app-store listings. The form collects: identification of the work, the URL or `doc_id` or `sha256` complained of, the complainant's authority, contact details, a good-faith statement and a signature. Anonymous notices are actioned on the merits; incomplete notices are actioned and then queried. | The address resolves to a monitored shared inbox with paging; a synthetic notice sent monthly is acknowledged within the SLA. |
| 06-TAKE-002 | The **acknowledgement is automatic and immediate** (≤5 min) with a `notice_id`; the substantive answer follows within the SLA. Never require an account, a login or a specific format. | Synthetic-notice drill measures both times. |
| 06-TAKE-003 | The in-product **"Report a problem"** on every citation chip (06.6) and every Mark routes rights complaints into the same queue with the `doc_id` and `chunk_id` pre-filled; accuracy complaints route to the content queue instead. The router is a one-question chooser, not a free-text triage. | Fixture: a rights report from a chip creates a `notice` row with the document resolved. |

### The 24-hour SLA

**06-TAKE-004** From receipt of any notice that identifies a document — however informally — to the document being dark: **≤24 hours**, clock running on weekends and holidays. The on-call takedown rota is the content lead and counsel, with the CTO as backstop; paging is the same rota as a P1 incident. **Assess after, not before:** the operator flips the kill switch first and evaluates the merits afterwards, because reinstatement is cheap and exposure is not.

| Step | Owner | Target |
|---|---|---|
| Acknowledge with `notice_id` | automatic | ≤5 min |
| Resolve the notice to `doc_id`s via the ledger (06-PROV-009: `sha256`, `source_url`, `doc_id` or title search) | on-call | ≤2 h |
| Flip `provenance_ledger.kill_switch = true` on every resolved document version | on-call | ≤4 h |
| Verify propagation with the automated proof (below) | on-call | ≤6 h |
| Substantive reply naming what was removed and the derived-row count | counsel | ≤24 h |
| Merits assessment; reinstate, keep dark, or negotiate a licence | counsel + founder | ≤10 working days |

### Kill-switch semantics

**06-TAKE-005** `kill_switch = true` is a single write with six mandatory consequences, executed by one job (`takedown_propagate`) that must complete or alert:

| Layer | What happens | Verified by |
|---|---|---|
| **Retrieval** | The prefilter drops every `chunk` whose `document_id` (or `derived_from` closure) hits the killed version, in the next query — no re-index, no deploy | 10,000-query probe returns 0 chunks |
| **Packs** | Every `items`, `mark_schemes`, `examiner_insights`, `textbook_sections`, `figures`, `exemplars` row derived from it is excluded from Pack builds and from practice selection; a Pack whose `mapped_pct` drops below its gate threshold returns to `mapped` (14-PACK-002) | Pack validation re-run; state change logged |
| **Caches** | Every prompt-cache key, CDN object and client cache whose manifest lists the `doc_id` is invalidated; TTLs are irrelevant because the manifest join is exact | Cache-manifest scan returns 0 live keys |
| **Live sessions** | In-flight Sessions finish their current Turn and then re-assemble context without the document; nothing already rendered is retracted from the screen, but the next Turn cannot cite it | Session-continuation test |
| **Exports** | Learning Receipts, Card exports, print views and offline bundles regenerate without the document; already-downloaded artefacts are out of reach and the reply says so plainly | Regeneration diff on a fixture Receipt |
| **Marks** | Existing Marks are **not** deleted (they are the audit record, 05-MARK-012) but their `sources[]` chips for the killed document render as "source withdrawn" and no longer deep-link; a Mark whose scheme record is killed cannot be re-marked or challenged against it | Chip-state test; challenge on a killed scheme returns the withdrawn state |

**06-TAKE-006** The switch is **per document version**, never per source or per board: killing `doc_id@3` does not kill `@2` unless the notice names it. Killing a document does not delete it — bytes and ledger row are retained under legal hold so that a counter-notice, a licence or a dispute can be answered. *Acceptance:* after a kill, `SELECT` on the ledger still returns the row with `takedown.removed_at` set and `kill_switch=true`.

**06-TAKE-007** `derived_from` closure is transitive and is the whole point: killing an official mark-scheme PDF must remove the OWN paraphrases and examiner insights derived from it, not just the anchors. This is test 4 of 06.1 and runs nightly on a random document. *Acceptance:* kill a random official document in staging → 100% of insights and paraphrases whose closure includes it disappear from retrieval within the propagation job's runtime (target ≤15 min, SLA 24 h).

**06-TAKE-008** USER documents use the same switch: a student's "Delete this file" is a self-service takedown with a 24 h propagation SLA (06-STOR-005) and writes the same ledger fields. There is no second deletion path.

**06-TAKE-009 DMCA designated agent.** Margin hosts USER uploads, so §512 safe harbour is available and its precondition is a registered agent. **Before the first public build**, register a designated agent with the US Copyright Office, keep the directory entry current (re-file on every change of name, address or agent, and on the Office's renewal cycle), and publish the same details at `/legal/notice` and in the footer alongside 06-TAKE-001's address. The agent is a named person with a postal address, not a role alias. *Acceptance:* the release checklist (§14.4) blocks the first public deploy until the registration number is recorded in the compliance folder; the quarterly counsel review (06-NONA-020) re-checks the directory entry.
